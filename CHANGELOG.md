# Changelog

Notable changes by release. Releases are git tags `vX.Y.Z`. New work goes under Unreleased.

## Unreleased

### Breaking changes

- `History` has two new public fields: `device` (a `DeviceKind`: the device the run trained on) and `device_note` (under `Device::Auto`, why a GPU that opened was left for the CPU). A `History { .. }` that names every field no longer compiles: add `device: Default::default(), device_note: None`, or end the literal with `..History::default()`.
- `GpuStepProfile` has a new public field, `backward_input`, and is now `#[non_exhaustive]`, so a later field is not a breaking change. Outside `cavitation-nn`, a `GpuStepProfile { .. }` literal no longer compiles and a pattern that destructures one needs `..`. Reading its fields is unchanged, and a profile still comes from `GpuTrainer::last_profile`.

### Tensors and autograd (`cavitation-core`)

- `Tape::softmax_cross_entropy`, `log_softmax` and `log_softmax_row` take `ln Σ e^(z − max)` as `ln_1p` of the sum without the first maximum's term, so a confident row's small loss keeps its relative accuracy: on rows `[0, −a, −a − 2, −a − 4]` labelled 0, for `a` from 8 to 20, the `f32` loss is within 2.1u of the `f64` one (`u = 2⁻²⁴`), where rounding `1 + e` to `f32` first gave a loss of exactly 0 once `e` fell below `u`. On 4,096 × 10 logits with the label's raised by 12, the mean relative error of the loss over 20 batches is +3.3u instead of −166u (Intel Celeron N5105). Losses, log-probabilities and the cross-entropy's gradient change in their low bits on such rows. A +∞ or NaN logit still gives a NaN row (#321).

### Layers, training and inference (`cavitation-nn`)

- `devices()` lists the devices this machine and this build can train on, best first: the GPU (with the `gpu` feature, the adapter `Gpu::open` picks, with the platform's other backends that also open it), then the CPU with its kernel level and thread count. A device that cannot be used is listed with the reason, such as a build without the `gpu` feature. Each `DeviceEntry` has its `DeviceKind` (`Cpu` or `Gpu`), name, detail, whether it is available, whether it is the chosen one, and a note; on an NVIDIA card the note says that NVIDIA's CUDA and cuDNN would train faster and that the library has no CUDA engine yet (#342).
- `Device::Auto` lets `fit` pick: the GPU when the build has the `gpu` feature, a GPU opens, the run has no hook and no `StepControl`, and a `GpuTrainer` can be built for it (every layer, the loss, the optimiser, the health settings and the validation set are ones the GPU trains); the CPU otherwise. `History::device` says which trained, and `History::device_note` gives the reason when a GPU that opened was left for the CPU (the error `Device::Gpu` would have returned); the health settings are looked at before the trainer is built, so a run they keep off the GPU compiles no shader. Each `Device::Auto` run opens the GPU anew. On the GPU the run is `Device::Gpu`'s on that GPU, bit for bit, and on the CPU it is `Device::Cpu`'s. `FitConfig::default()` still trains on the CPU. The pick does not weigh the model's size. Measured on an NVIDIA GTX 1660 Super (Vulkan) and an AMD Ryzen 7 2700X (avx2, 16 threads) with `cavitation-bench <net> --cav-only --rows 12800 --epochs 3 --device cpu|gpu|auto` (built with `--features gpu`), the steady epoch of 12,800 rows takes 0.45 s on the GPU against 0.97 s on the CPU for `mnist-cnn` and 2.54 s against 14.21 s for `cifar-cnn`, and `auto` trains on the GPU (0.44 s and 2.54 s); on the digits network's shape (64 → 256 → 128 → 10) at batch 32 an epoch of 36 steps takes 19.9 to 20.8 ms on the GPU against 18.9 to 19.5 ms on the CPU (`CAVITATION_GPU_BACKEND=vulkan cargo test --release -p cavitation-nn --features gpu --lib epoch_time_of_a_small_network_by_device -- --ignored --nocapture`, two runs), so a GPU gains nothing there.
- The environment variable `CAVITATION_DEVICE` (`auto`, `cpu` or `gpu`) restricts what `Device::Auto` and `devices()` choose; it does not change a run that names `Device::Cpu` or `Device::Gpu`. With `gpu`, a run the GPU cannot train is an error and does not fall back to the CPU. Any other value is an error that names the values accepted.

### GPU

- A new crate, `cavitation-cuda`, the base of a CUDA engine for NVIDIA cards (#342, phase 2). It links nothing and has no dependencies: the CUDA driver, cuDNN 9, and cuBLAS and NVRTC of the CUDA major version cuDNN was built for (12 or 13) are found and loaded when the program runs, so a build starts on a machine without them. `Cuda::open` says what is missing and what to install, and `Cuda::new` returns `None` (or panics under `CAVITATION_CUDA_REQUIRED=1`). The libraries are looked for in the folders of `CAVITATION_CUDA_PATH`, `CUDNN_PATH` and `CUDA_PATH` (with their `bin`, `bin/x64`, `lib`, `lib64` and `lib/x64`), then in those of `PATH` (Windows) or `LD_LIBRARY_PATH` and the linker's own (Linux); neither they nor the libraries they import are looked for in the folder the program was started in (on Windows the imports come from their own folder and the system folder only, and on Linux nothing is loaded while `LD_LIBRARY_PATH` holds an empty or relative folder), and the libraries NVIDIA's code is known to load by name later (cuDNN's parts, cuBLASLt, NVRTC's built-ins, `zlibwapi.dll`) are loaded first from beside the one that needs them. A cuDNN built for a CUDA other than 12 or 13 is refused by name. and macOS has no CUDA. A driver older than NVRTC, and a card older than every architecture NVRTC compiles for, are reported by `Cuda::open`. `Cuda` holds the first card's primary context and a cuDNN and a cuBLAS handle, `CudaInfo` names the card, the versions and the files loaded, `DeviceBuffer` is zeroed memory on the card written from and read into `f32`, `u32` or `i32` slices, and `Cuda::compile`, `Module` and `Kernel::launch` run CUDA C++ compiled by NVRTC with `--fmad=false`, so a kernel's `a * x + y` has the host's bits, for the card's compute capability or the newest older one NVRTC knows (`CudaInfo::compiles_for`). Every call makes the card's context current on the thread first, and dropping the last `Cuda` leaves none current. Nothing calls a cuDNN or cuBLAS routine yet, and nothing in `cavitation-nn` trains through it. `cargo run --release -p cavitation-cuda --example cuda_info` prints what was found; on an NVIDIA GTX 1660 Super with driver 591.86 it opens cuDNN 9.24.0 (built for CUDA 13.3), cuBLAS 13.0.0 and NVRTC 13.0.
- The GPU GEMM and the three convolution kernels built on it (forward, input gradient, weight gradient) have a second tile shape, 32 × 128 outputs per workgroup (each thread a 2 × 8 block), for a product of at most 32 rows: on the 64 × 64 tile, 32 rows leave half of each workgroup's accumulators adding zeros. Each output is still its products added in increasing k, so it has the same bits on either tile. The wide tile is chosen per call when the product has at most 32 rows, more than 64 columns and at least 64 wide tiles in its dispatch; below that the square tile's doubled workgroups fill the GPU better and it is kept (measured: the wide tile takes 1.45 times the square tile's time at 8 workgroups, 1.38 at 24, 0.93 to 1.11 at 32, 0.72 to 0.73 at 64 and 0.64 to 0.71 from 128 up). Measured on an NVIDIA GTX 1660 Super with `gemm-gpu --shapes`: 128 products of 32 × 1024 × 288 (a 32-channel convolution's forward pass at batch 128) take 1.58 ms against 2.43 ms. A `cifar-cnn` training step at batch 128 takes 25.4 ms against 28.3 ms on Vulkan and 27.1 ms against 30.1 ms on DX12 with DXC; the 32 → 32 convolution's forward pass 2.10 ms against 2.94 ms and its backward pass 5.90 ms against 7.23 ms (Vulkan). The wide tile's pipelines are built only for the calls that use them, by the new `ensure_wide` of `Gemm`, `ConvForward`, `ConvInputGrad` and `ConvWeightGrad`, which `GpuModel` and `GpuTrainer` call when they compile; a call it was not asked for runs on the square tile. A model with no such call compiles as before. On DX12 the wide tile is used only when DXC is named as the shader compiler (`WGPU_DX12_COMPILER=dxc`): FXC takes about 27 s over each wide pipeline (a `cifar-cnn` trainer built in 244 s with them against 134 s without), and DXC about 1 s. On Metal the wide tile is not used: on an Apple M4 it is slower than the square tile on every product the rule gives it, 1.13 to 1.79 times its time, and a `cifar-cnn` epoch took 22.75 s against 22.47 s.
- `kernels::SoftmaxCrossEntropy` takes `ln Σ e^(z − max)` as `ln(1 + e)`, with `e` the sum without the first maximum's term, and for `e ≤ 1` from the series of `2·atanh(e / (2 + e))` instead of WGSL's `log`, whose error near 1 is 2⁻²¹ absolute. On confident rows (4,096 × 10 logits, the label's raised by 12, 20 batches) the loss's mean relative error against `f64` is +1.2u instead of −26.5u on an Intel UHD Graphics (JSL) through Vulkan; the stated bounds are tightened to match (#316).
- `GpuStepProfile::backward_input` is, for a `Linear` or a `Conv2d`, the part of the layer's `backward` time that is its input gradient, timed in a compute pass of its own; the rest is the layer's parameter gradients. It is `None` for every other layer and for a first layer, which computes no input gradient. `backward` is still the whole layer, and a step that is not profiled records the same calls as before. Measured on an NVIDIA GTX 1660 Super through Vulkan with `CAVITATION_GPU_BACKEND=vulkan cargo test --release -p cavitation-nn --features gpu --lib backward_parts_of_a_cifar_step -- --ignored --nocapture` (a `cifar-cnn` training step at batch 128 with Adam, medians of 11 profiled steps, two runs within 1%): the four convolutions' parameter gradients take 0.700, 3.101, 1.105 and 1.910 ms and the last three's input gradients 2.784, 1.487 and 1.990 ms, 6.82 ms against 6.26 ms; the 32 → 32 convolution's backward pass is 5.91 ms, as before the split (#311).

### Data, examples, guide and benchmark

- `cavitation-bench mnist-cnn` and `cifar-cnn` name Cavitation's side `cav`, short for Cavitation, where they said `ours`: the option `--ours-only` is now `--cav-only`, the printed lines read `cav   epoch`, `final test accuracy: cav`, `steady epoch time: cav` and `cav / torch`, and `result.json`'s key `ours` is `cav`. The old option is not accepted.
- `cavitation-bench devices` prints the device list with the chosen device marked and how to choose another, and `mnist-cnn` and `cifar-cnn` take `--device auto`.
- `cavitation-bench gemm-gpu` takes `--shapes MxNxK[xBATCH],...`: products of any shape (`C` is `M` by `N`), each optionally as a batch of products in one dispatch, timed like the squares. `--sizes none` times no squares.

## v0.4.1 (2026-11-17)

Training on the GPU now runs end to end: `fit` takes `FitConfig::device`, and `Device::Gpu(&gpu)` (with the `gpu` feature) trains through the new `GpuTrainer`, with the CPU run's batches, learning rates, dropout masks and health checks, a short last batch included. `GpuModel` runs a compiled model in evaluation mode (`infer_batch`, `evaluate`, `accuracy`), and `GpuTrainer::profile_next_step` times each layer on the GPU. The kernels gain the convolution's weight gradient and a neuron mask. On the CPU, `Sequential` fuses a batch norm with the ReLU after it by default, and convolution backward passes are faster. Two changes are breaking: the new `FitConfig::device` field, and the fused pair's trace and hooks behaviour; both entries below say how to keep the old behaviour.

### Breaking changes

- `Sequential` fuses a `BatchNorm2d` followed directly by a plain `Relu` by default, so for such a pair at layers `i` and `i + 1`, `Trace::output(i)` and `Trace::input(i + 1)` are now the ReLU's output, not the batch norm's. Code that read the batch norm's own output from a trace, or took a gradient at it, now gets the ReLU's. To get the old behaviour, call `trace.keep_output(i)` (or `trace.keep_all_outputs()`) before `forward_traced`, or build the network with `.fuse(false)`.
- `Hooks::run_forward` and `Hooks::run_backward` now panic, naming the layer, when a hook watches a fused batch norm or the ReLU after it. To get the old behaviour, call `hooks.keep_outputs(&mut trace)` before `forward_traced` (`fit` already does), or build the network with `.fuse(false)`.
- `FitConfig` has a new public field, `device` (`Device::Cpu` by default), with or without the `gpu` feature. A `FitConfig { .. }` that names every field no longer compiles: add `device: Default::default()`, or end the literal with `..FitConfig::default()`.

### Tensors and autograd (`cavitation-core`)

- A convolution's bias gradient sums each output channel on a thread of its own (one task per channel, each sum in its old order, so the gradient is the same bits for any thread count). It was one chain of additions on one thread: on the `mnist-cnn` network at 4 threads on an Intel Celeron N5105, the first convolution's backward pass takes 1.67–1.71 ms instead of 1.89–1.93, and the step 9.14–9.38 ms instead of 9.53–9.68 (#201).
- `Tape::batch_norm2d_relu` records batch normalisation followed by ReLU as one node. Its values, gradients and running statistics are the same bits as `batch_norm2d` then `relu`, with one pass over memory fewer in each direction: the forward pass applies ReLU as it writes, and the backward pass multiplies the gradient by ReLU's derivative inside batch norm's own two passes.
- At the NEON level the direct f32 weight gradient of a 3 × 3 convolution (stride 1, padding 1, dilation 1, width a multiple of 4) takes three output channels per pass, 27 accumulators, so each padded-input load feeds three fused multiply-adds, and runs for any number of input channels; it ran only for at most 4. Each sum's order is unchanged, so it still matches `conv3x3_direct_weight_grad_twin` bit for bit. On an Apple M4 at 4 threads (`CAVITATION_KERNEL=neon`, `cifar-cnn --profile 9`, batch 128, medians of interleaved runs), the backward passes of the `cifar-cnn` network's convolutions take 0.68, 12.76, 6.53 and 12.93 ms instead of 1.06, 16.26, 7.36 and 14.60 with im2col and the GEMM on the last three, and the whole step 67.4 ms instead of 73.8 (#284).

### Layers, training and inference (`cavitation-nn`)

- `Sequential` records a `BatchNorm2d` followed directly by a plain `Relu` as one node (`Tape::batch_norm2d_relu`), on by default and turned off with `Sequential::fuse(false)`. Values, gradients and running statistics are unchanged, bit for bit. A pair is not fused when either layer has a mask or a trace asks for the batch norm's own output: `Trace::keep_output` and `Trace::keep_all_outputs` ask, `Trace::fused` says which pairs were fused, and `Sequential::fuses_at` says which would be. `fit` keeps the layers its hooks watch, the inspector's probe and shrink's activity statistics keep every layer, and `Hooks::keep_outputs` does the same for a hand-written loop; `Hooks::run_forward` and `run_backward` now panic, naming the layer, on a trace whose hooked layer (or the layer before it) was fused: a hand-written loop that hooks a batch norm or the ReLU after it calls `hooks.keep_outputs(&mut trace)` before `forward_traced`, or turns fusion off. `Trace::clear_kept` forgets the kept layers. Compacting or retraining a shrunk model keeps the model's fusion setting. A fused batch norm's profile entries carry the pair's times, and `cavitation-bench --profile` marks the ReLU's row.

### GPU

- `OptimizerKernel`'s docs give plain SGD's value bound, where the backend rounds its `fma` twice, as `u·|p'| + u·(1 + u)·lr·|g|`; it was stated as `u·(|p'| + lr·|g|)`, which leaves out the second-order term (#287).
- The `cavitation-gpu` docs state the rounding its kernels assume: each f32 operation rounded to nearest, within `u = 2⁻²⁴`, with ties to even where a kernel matches the CPU bit for bit. WGSL leaves the rounding mode open, so on a backend that rounds another way each rounding's `u` becomes `2u`. A new test, `crates/cavitation-gpu/tests/rounding.rs`, checks f32 `+` and `*` on cases just above, just below and exactly at halfway points, and fails by name on a backend that does not round to nearest, ties to even (#288).
- Profiled steps time each compute pass and, where the device offers `TIMESTAMP_QUERY_INSIDE_ENCODERS` (Vulkan and DX12; not Metal on Apple GPUs), each run of copies (uploads, clears, readbacks) between passes inside a span, from timestamps written on the encoder. `StepOutput::timed` gives each entry (`Timed`: its span, `TimedKind::Pass` or `Copies`, and its nanoseconds) in the order recorded, and a span's time in `StepOutput::spans` is the sum of its entries'. `StepEncoder::timing` says what is timed (`Timing::PassesAndCopies`, `Passes` or `Untimed`) and names the missing feature or setting for the rest. `GpuInfo::encoder_timestamps` says whether the feature was requested, and `GpuInfo`'s display prints it. The query set and readback keep room for as many copy runs as `StepSizes::timed_passes`.
- A timed pass whose end timestamp reads before its beginning now has no time (`None`), and neither has its span; it counted as 0.
- Span times on Metal are the step's own: the timestamps were resolved in the step's own command buffer, which on Metal read the counter samples of the step before, so each span had the previous step's time. They now resolve in a submission of their own after the step's has finished. `cavitation-bench gemm-gpu`, which times the same step over and over, gives the same medians as before (within 0.3% on an Apple M4).
- `kernels::ConvWeightGrad`: the 2-D convolution's weight gradient on the GPU, NCHW, with stride, padding and dilation, for a batch of images in one call. It is an implicit GEMM through the tiled GEMM's core over the batch's `batch · oh · ow` output positions, cut into fixed blocks of `WEIGHT_GRAD_BLOCK` (1,024) consecutive positions: each block sums its positions in the CPU reference's order (image, output row, column) into a partial gradient of its own, and a second pass adds the partials in block order and overwrites the weight gradient, with no atomics. The blocks depend only on the shape, so runs give the same bits. With `L` positions per block and `B` blocks it is within `2(L + B + 2) · u · Σ|dy·x|` of `conv2d_backward_reference`'s weight gradient in f64, and exact on small integers, the `cifar-cnn` network's first two convolutions at batch 128 (131,072 positions in 128 blocks) included, checked on an Apple M4 (Metal).
- `GpuModel::compile(&model, &params, batch, &gpu)` (in `cavitation-nn`, behind `gpu`) compiles a `Sequential` for batches of `batch` rows on the GPU: `Linear`, `Conv2d`, `MaxPool2d`, `AvgPool2d`, `BatchNorm2d`, `Dropout`, `Flatten`, `Identity`, and the activations `Relu`, `LeakyRelu`, `Tanh`, `Sigmoid` and `Gelu` (both forms). Any other layer, including a layer of your own that has parameters, is refused with `Error::Unsupported` naming its index and name; widths that do not chain, and masks that are not as wide as their layer's output, are `Error::InvalidData` naming the layer. Each parameter and batch-norm running statistic is uploaded under its `ParamId`, in one step, and comes back bit for bit (signed zeros, NaN payloads, subnormals and infinities included; checked on Vulkan and DX12); `num_batches_tracked` stays on the host. Neuron masks set on the model are compiled in as one bit per value of the batch. Running the model follows in the next changes (#297).
- `GpuModel::infer_batch`, `GpuModel::evaluate` and `GpuModel::accuracy` run a compiled model in evaluation mode, as the CPU tape does: dropout passes its input on, batch norm uses its running statistics (or the batch's when it keeps none), and neuron masks apply. A batch is one GPU step (one upload, the layers' kernels, one readback), and up to the compiled batch size of rows run per step: each row's outputs depend on that row alone, so a short batch gives the full batch's rows bit for bit. A batch norm that keeps no running statistics needs whole batches, and a short one is refused. `evaluate` measures the loss, accuracy and R² as `evaluate` does on the CPU, from the GPU's outputs. Each layer's output is checked against the `f64` tape's layer on the GPU's own input, within that kernel's bound, on a masked MLP, `mnist-cnn` and `cifar-cnn`; end to end, the outputs are within 1.1e-6 of the `f64` tape (NVIDIA GTX 1660 Super, Vulkan). On that card, compiling a model takes about 1 s on Vulkan, 6 s on DX12 with DXC and 90 s on DX12 with FXC, the fallback when `dxcompiler.dll` is not found (#301).
- `GpuTrainer` trains a `Sequential` on the GPU one batch at a time: `GpuTrainer::new(&model, &params, &optimizer, loss, batch_size, &gpu)` and `step(&model, batch)`. A step is one command encoder and one readback (the loss, the finite flag and the health values): the batch, its targets and its dropout masks go up; the training forward pass (dropout with the CPU tape's masks from `dropout_mask`, batch norm from the batch's statistics) runs; then the loss, the backward pass through every layer, the finite flag, the optimiser's update and batch norm's running statistics. While a full step runs on the GPU, the next full step's masks are drawn on the host. The update and the running statistics are skipped when the loss or a gradient is not finite, and `step` returns `Error::NonFinite` under the health checks' default, `OnNonFinite::Stop` (see the health checks below). `sync_to(&mut params)` copies the parameters, running statistics and batch counts back; `optimizer_state()` gives the update counts and moments; `model()` evaluates the parameters as they are, without a sync. The losses are cross-entropy and MSE, and the optimisers SGD (with momentum and weight decay), Adam and AdamW; RMSprop, Adagrad and parameters shared by two layers are refused. Each parameter's gradient is in its own buffer and is copied into the optimiser's flat buffers within the step. `Step::copy` copies between two GPU buffers inside a step.
- `GpuTrainer` runs the CPU trainer's health checks on every step, on values the step reads back with its loss: the finite flag, each gradient's count of NaN and infinite values (`FiniteFlagCall::counts`) and sum of squares (`SumSquares`), and each ReLU neuron's bit for the step (`DeadRelu`, one per channel after a convolution). It sends the CPU's warnings (non-finite values, exploding and vanishing gradient norms, dead ReLU neurons) and returns the CPU's errors at the same steps and naming the same parameters, through `GpuTrainer::set_health`, `end_epoch` and `skipped_steps`, as `Trainer` has them; `GpuTrainer` now carries the sink's lifetime, `GpuTrainer<'s>`. Under `OnNonFinite::Skip` a step whose loss or gradient is NaN or infinite is left out and counted, with Adam's update counts unchanged. A step with a NaN or infinite loss or gradient is never applied on the GPU, so under `OnNonFinite::Stop` the parameters, the optimiser's state and the running statistics stay as they were, where the CPU trainer has already applied a non-finite gradient that came with a finite loss; `OnNonFinite::Warn` is refused. On an Apple M4 the checks add about 1 ms to a `cifar-cnn` step at batch 128 (57.3 against 56.2 ms, medians of three rounds of 21 steps; 56.5 ms with the dead-ReLU check off).
- `GpuTrainer::step` takes a batch of fewer rows than the trainer's batch size, as an epoch's last batch is: the first one compiles a training step for that many rows, kept for the run (one per row count), which shares the parameters, the optimiser's state and batch norm's running statistics with the full step and has buffers of its own for every value, gradient and mask, sized for its rows. A NaN in such a batch is stopped or left out through the short step's own finite flag. `RunningUpdate::set_count` lets the two steps' updates of one batch norm share its batch count, for a cumulative average. On two epochs of 50,000 rows at batch 128 (390 batches, then one of 80) every step's loss is within 2⁻¹⁰ of the CPU trainer's.
- `GpuTrainer::profile_next_step` and `last_profile` time one step on the GPU, as `Trainer`'s do on the CPU: a `GpuStepProfile` gives each layer's forward and backward time, the loss, the health values, the optimiser's update, the copies into and out of its flat buffer and the readback (where the adapter offers `TIMESTAMP_QUERY_INSIDE_ENCODERS`: Vulkan, DX12, OpenGL with `GL_ARB_timer_query`, and Metal on AMD and Intel GPUs, not Apple's), batch norm's running statistics and the whole step on the host's clock. A part the device cannot time is `None`, and `GpuStepProfile::timing` names what is missing. The profiled step runs each part in compute passes of its own; a step left out under `OnNonFinite::Skip` passes the request to the next. A model too deep for wgpu's 4,096 timestamp queries (about 1,000 layers, or 500 with encoder timestamps) is not timed.
- `fit` trains on the GPU: `FitConfig::device` takes `Device::Cpu`, the default, or, with the `gpu` feature, `Device::Gpu(&gpu)`. On a GPU the run is the CPU run's batches, learning rates, dropout masks and health checks through a `GpuTrainer` made for `FitConfig::batch` rows, the shorter last batch included, with `FitConfig::validation` measured by the trainer's `GpuModel` in evaluation mode. The parameters stay on the GPU and are copied back into the `ParamStore` before each `on_epoch` call, when early stopping keeps an epoch as the best so far (`restore_best`), before an error met during training is returned, and at the end; a run with no callback and no best epoch to keep copies them back once. `fit_controlled`, `fit_with_hooks` with a hook registered, and what `GpuTrainer` refuses (RMSprop, Adagrad, a loss other than cross-entropy and MSE, `OnNonFinite::Warn`) return `Error::Unsupported` before any training. A step whose loss or gradient is NaN or infinite is never applied on the GPU, so under `OnNonFinite::Stop` the returned parameters are those before that step. Measured on an NVIDIA GTX 1660 Super (Vulkan and DX12): the run is the hand-written `GpuTrainer` loop bit for bit; on the digits (64 → 64 → 32 → 10, Adam, batch 32, 5 epochs, seeds 0 to 4) the final training loss is within 5e-7 of the CPU run's, relative, and the held-out accuracy is the CPU's on every seed.
- `kernels::Elementwise::KeepWhere`: a neuron mask on the GPU, from the same bit-packed mask as dropout. It selects each value where its bit is set and gives +0 where it is clear, as `Tape::keep_where` does, so a cleared NaN or −3 is +0. `Elementwise::ALL` holds 17 operations.

### Data, examples, guide and benchmark

- `cavitation-bench conv --parts` also prints each convolution's backward pass in two halves, the weight gradient and the input gradient, from a third timed step that takes no input gradient.
- `cavitation-bench mnist-cnn` and `cifar-cnn` take `--device gpu` (with the `gpu` feature) to train our side with `GpuTrainer` on the GPU, from the same initial weights, batch order and dropout seed as the CPU run, and `--backend vulkan|dx12|metal` to pick the backend. `--torch-device cpu|cuda|mps` and `--deterministic` choose where and how the PyTorch side trains, and `scripts/bench/torch_cnn.py` gains `--device mps` and `--deterministic`. With the `gpu` feature, `cavitation-bench info` prints the GPU.
- `scripts/bench/torch_cnn.py --device cuda` trains the PyTorch side of `mnist-cnn` and `cifar-cnn` on a CUDA GPU, from the same initial weights and batch order, with each step timed between `torch.cuda.synchronize()` calls and a median step time over every epoch but the first. `cudnn.benchmark` stays False unless `--cudnn-benchmark` is given. The CPU default's output is unchanged.

## v0.4.0 (2026-11-16)

This release adds the `cavitation-gpu` crate, behind the `gpu` feature: device setup, buffer and pipeline reuse, one-submission steps, and GPU kernels for most of a training step (the GEMM, the convolution's forward pass and input gradient, pooling, element-wise layers, batch norm, the optimisers, the losses and the health values), each checked against its CPU twin. Training on the GPU through `fit` is not built yet: nothing in `cavitation-nn` runs these kernels, and the GPU model, trainer and device selection follow in 0.4.x releases. A default build has no wgpu in it. On the CPU, 3 × 3 convolutions run directly at the SIMD levels, and CNNs can now be shrunk by channel.

### Breaking changes

- `shrink::ShrinkConfig::linears` is now `layers`, and holds `Conv2d` indices as well as `Linear` ones; `shrink::RankContext::linear` is now `layer`, and `RankContext` gives the unit statistics as the slices `mean`, `mean_abs`, `firing` and `max` in place of `activity: &LayerActivity`, so that one custom ranking serves neurons and channels (#209).

### Tensors and autograd (`cavitation-core`)

- More backward passes write a value's first gradient contribution instead of zeroing its buffer and adding. `max_pool2d`'s backward pass zeroes each block of planes on the thread pool just before adding to it, instead of zeroing the whole input gradient in one pass first; on an Intel Celeron N5105 at 4 threads, the `cifar-cnn` network's two poolings take 5.9–6.5 ms of backward time per training step instead of 9.5–10.4 (three interleaved rounds of `cifar-cnn --profile 9`, machine under load). `mul`, a broadcast `add` or `sub`, and `keep_where` write their first contribution straight into the gradient buffer instead of through a scratch buffer and a copy. The results are unchanged, bit for bit (#248).
- The derivative of `gelu` is no longer NaN at very large |x|: the tanh form's backward pass gave `0 · ∞ = NaN` in f32 once `x²` overflowed (|x| from about 1.8e19), and the exact form at ±∞. Where the second term's small factor is exactly 0 (`tanh` saturated, or the density underflowed) the term is now dropped, which gives the derivative's limits, 1 and 0. Every other value keeps its bits (#268).
- `sum` and `mean` over a whole tensor, and `sum_axis` and `mean_axis` over the last axis, run one plain running sum per output, and their backward passes divide each output gradient once and write it with `fill`. The results are unchanged, bit for bit. On an Intel Celeron N5105, `sum` over a `[128, 32768]` f32 input takes 4.7–4.9 ms forward instead of 15.7 and 2.1–2.6 ms backward instead of 10.7 (three interleaved runs, medians of 21) (#234).
- A 3 × 3 convolution with stride 1, padding 1 and dilation 1 runs its forward pass and its input gradient as a direct convolution in f32 at the SSE4.2, AVX2 and NEON levels, where the output channels (for the input gradient, the input channels) are a multiple of 4 and the width a multiple of the vector width (`kernels::conv::conv3x3_direct`, `conv3x3_direct_input_grad`, `direct_runs`, `direct_input_grad_runs`, `direct_scratch`). Each image is copied once into a zero-padded buffer and every output is summed over the input channels and taps in a fixed order, with no column matrix; the weight gradient, f64, the Accelerate level and every other geometry keep im2col and the GEMM. On an Intel Celeron N5105 at 4 threads (batch 128, interleaved medians, machine under load), the `cifar-cnn` network's convolutions take 6.6, 70.1, 34.1 and 82.6 ms forward instead of 12.7, 89.3, 37.1 and 88.1, and the input gradients of the last three 70.9, 33.2 and 83.4 ms instead of 78.8, 33.4 and 90.3. The results stay the same for any thread count, and `InferenceModel` runs the same kernel, so it still agrees with the tape bit for bit; they differ from v0.3's in the last bits, within the bound of the sum. Each kernel matches its scalar twin, `conv3x3_direct_twin`, bit for bit (#246).
- The f32 weight gradient of a 3 × 3 convolution with stride 1, padding 1 and dilation 1 runs directly at the SSE4.2 and AVX2 levels, and at NEON for at most 4 input channels (where it measured faster than the GEMM on an Apple M4; with 32 and 64 input channels the NEON GEMM is faster), where the width is a multiple of the vector width (`kernels::conv::conv3x3_direct_weight_grad`, `direct_weight_grad_runs`, `direct_weight_grad_scratch`). Blocks of up to eight output channels are tasks; each copies every input plane into a zero-padded buffer once and sums `dy · x` for each tap with one accumulator per vector lane, the lanes added as a tree, image after image, with no column matrix. On an Intel Celeron N5105 at 4 threads (batch 128, medians of 10 interleaved runs, machine under load) the weight gradients of the `cifar-cnn` network's convolutions take 5.7, 51.9, 25.5 and 54.8 ms instead of 17.7, 87.1, 41.1 and 82.9 with im2col and the GEMM, and the whole training step 721 ms instead of 823 (medians of four interleaved `cifar-cnn --profile 9` rounds, load average 5 to 7). The result does not depend on the thread count; it differs from the GEMM path's in the last bits, within the bound of the sum. Each kernel matches its scalar twin, `conv3x3_direct_weight_grad_twin`, bit for bit (#201).

### GPU

- A new crate, `cavitation-gpu`, reached through the `gpu` feature of `cavitation` (re-exported as `cavitation::cavitation_gpu`) or of `cavitation-nn`, both off by default; a default build has no wgpu in it. `Gpu::new()` opens the best hardware GPU on Vulkan, Metal or DX12 through wgpu 30 (Metal on macOS; Vulkan, then DX12 on Windows; Vulkan elsewhere), preferring a discrete GPU and trying the next adapter if a device fails to open, and returns `None` when there is none; software renderers, CPU and virtual adapters, paravirtual devices and OpenGL are left out. `Gpu::with_backend` asks for one backend and `Gpu::open` says why none could be opened. The device has up to 32 KiB of workgroup memory (less if the adapter has less) and GPU timestamps when the adapter offers them; `Gpu::info()` describes the adapter, driver and limits, and prints them through `Display`. `CAVITATION_GPU_BACKEND` (`vulkan`, `dx12` or `metal`) restricts every `Gpu` to one backend, and `CAVITATION_GPU_REQUIRED=1` turns a missing GPU into a panic, for test runs that must use the GPU. On DX12, shaders compile with DXC when `dxcompiler.dll` loads and with FXC otherwise; `WGPU_DX12_COMPILER=dxc` requires DXC.
- `cavitation_core::dropout_mask(seed, step, stream, p, len, write)` draws the dropout mask a training tape draws, without a tape, so a device that applies dropout itself drops the same values. `Tape::dropout` draws through the same code, and its masks are v0.3's, bit for bit (checked against a v0.3 fixture).
- `BufferPool` hands out GPU buffers by size class and usage and reuses those handed back. Up to 4 MiB a class is the request rounded up to a power of two (at least 256 bytes); above, to a quarter step between powers of two, so a large buffer is at most a quarter larger than asked for. Lengths are whole 4-byte words, within the device's binding limits. The pool counts the buffers and bytes it creates (`created`, `created_bytes`) and the buffers still out (`outstanding`), so a loop that takes and gives back the same sizes can show it creates buffers in its first pass only. `PooledBuffer::binding` binds only the bytes asked for, so a shader's `arrayLength` sees the request, not the class.
- `PipelineCache` builds each compute pipeline once per `Shader`, entry point, set of `override` values (in any order) and layout, and counts what it builds. `get` uses the layout wgpu derives from the shader; `get_with_layout` takes an explicit one, so one bind group serves every pipeline built with it. A shader that does not compile (in naga or in the backend's compiler), a missing entry point, or an unknown or NaN `override` is `GpuError::Shader` with wgpu's message, and nothing is cached for it. A workgroup array sized by an `override` constant works on Vulkan and on DX12 with DXC and with FXC.
- `StepEncoder` records one step's work in one command encoder and submits it once. `Step::upload` copies through a mapped staging buffer inside the encoder, so uploads run in order with the step's dispatches (unlike `Queue::write_buffer`, which runs before the whole submission); `Step::clear` zeroes a range; `Step::dispatch` takes up to 65,535 workgroups and `Step::dispatch_split` more, over two dimensions, for kernels that number their workgroups as `x + y · num_workgroups.x`; `Step::read_back` gathers results into one readback buffer; and `Step::finish` submits, waits and returns them as `StepOutput`. The staging, readback and timestamp buffers are made once, sized by `StepSizes`; `StepEncoder::buffers_made` and `StepEncoder::bind_group` count what is made, so a test can show warm steps create no buffers, bind groups or pipelines. With `set_profiling(true)`, each `Step::span` runs in timed compute passes of its own, and `StepOutput::spans` gives each span's GPU time, the sum of its passes' own times (on Metal, the passes on either side of a copy are not on one timeline, so a span an upload splits can read low). On an NVIDIA GTX 1660 Super, a warm step of an upload, three dispatches in two spans and a readback makes a fixed number of host allocations in wgpu (62 on Vulkan, 57 on DX12; 74 and 69 profiled), and the live host memory is the same after every step.
- `cargo run --release -p cavitation-gpu --example gpu_probe` lists every GPU adapter wgpu offers and whether cavitation would use it. For each backend it can open, it prints the features and limits the kernels depend on, and runs probe shaders showing how that backend's compiler treats floating point: whether `a * b + c` is fused, whether sums are reassociated, whether subnormals are flushed, and how NaN behaves under comparisons, `max` and a bit test.
- `kernels::MaxPool2d` and `kernels::AvgPool2d`: 2-D max and average pooling on the GPU, forward and backward, for one geometry and batch size, built once with the geometry as `override` constants. Max pooling forward gives the bits of `max_pool2d_reference`: the same winners (as `u32` positions in the plane), ties to the first tap, the last NaN of a window winning, and the winner's bits copied, signed zeros, subnormals and NaN payloads included; it compares values as integers ordered as the floats are, so fast math and subnormal flushing cannot change a winner. Max pooling backward adds each input's gradients in `max_pool2d_backward`'s order and gives its bits on normal values where the backend keeps that order (measured on Metal on sums that round); a subnormal sum is flushed. Average pooling follows `avg_pool2d`'s divisor rules (`count_include_pad`, `divisor_override`, `ceil_mode`'s clipped windows) and, on normal inputs, is within `(2(n + 2) + 6) · 2⁻²⁴ · Σ|x| / d + 2⁻¹²⁶` forward and `(2(m + 3) + 5) · 2⁻²⁴ · (|dx| + Σ|dy / d|) + 2⁻¹²⁶` backward. Both backward passes gather, one thread per input pixel, so they use no atomics and give the same bits on every run. Checked against the CPU twins on an Apple M4 (Metal).
- `kernels::OptimizerKernel` runs an `OptimizerRule` (SGD with momentum and weight decay, Adam, AdamW, every setting explicit) over a model's parameters in flat buffers, in one dispatch: a table maps each workgroup to one parameter's run of elements, and the sizes and per-parameter constants are in buffers, so one pipeline serves every model with the same rule. Each parameter keeps its own update count for Adam's bias corrections. `record` uploads the step's constants and dispatches, the kernel does nothing when the step's finite flag is set, and `commit` counts the update only for the parameters it ran on and only when the step ran, so a skipped step leaves values, moments and counts unchanged. The arithmetic is the CPU optimisers' in `f32`: against the exact result of the `f32` constants, plain SGD is within one rounding where the backend fuses `fma` (Metal, Vulkan and both DX12 compilers on the cards measured), and the other rules within the bounds the docs state, which hold whether each `fma` rounds once or twice (FXC splits Adam's) and allow for WGSL's 2.5-ulp division and its square root. Checked on an Apple M4 (Metal) over 50 steps of eight rules, each step from the GPU's own state, against arithmetic pinned bit for bit, step by step, to `cavitation-nn`'s `Sgd`, `Adam` and `AdamW`.
- `kernels::Gemm`: the tiled GPU matrix product `C = A·B + β·C` in f32 for any sizes, with either operand transposed (through `override` constants) and `β = 0` never reading the old `C`. Each 16 × 16 workgroup computes a 64 × 64 tile, 4 × 4 outputs per thread in named `vec4` accumulators, through 8.25 KiB of workgroup memory, padded against bank conflicts; each output adds its products in increasing k, so it is within `2(k + 3) · u · (Σ|a·b| + |β·c|)` of the exact product to first order, exact on small integers, and the same on every run. `Gemm::call` prepares a product on given buffers once (its dimensions uniform and its bind group), and `Gemm::record` adds it to a step. `cavitation-bench gemm-gpu` (with the bench's new `gpu` feature) times it: on an NVIDIA GTX 1660 Super, at 4096³, 1,717 GFLOPS on Vulkan and 1,665 on DX12 with DXC, and 1,727 and 1,644 with `B` transposed (medians of 20, GPU timestamps).
- `kernels::GemmDims` describes sub-matrices and batches: leading dimensions `lda`, `ldb` and `ldc` (0 for packed), element offsets for `A`, `B` and `C`, and `batch` products along the grid's z axis with per-product strides (0 shares a matrix, as one weight matrix serves every image of a convolution). `a_extent`, `b_extent` and `c_extent` give the f32s each buffer must hold. `Gemm::call` checks the extents and refuses to write `C` into the buffer `A` or `B` is read from. The shader is now a head (declarations), default loaders and a core, so a kernel can supply its own loaders.
- `kernels::ConvForward`: the 2-D convolution forward pass on the GPU as an implicit GEMM, NCHW, with stride, padding, dilation and an optional bias, for a batch of images in one dispatch. It reads the image windows as the GEMM's tiles are filled, so nothing is unfolded into memory, and adds each output's products in the CPU reference's order: within `2(k + 3) · u · (Σ|w·x| + |bias|)` of the f64 convolution, `k` = in·kh·kw, and exact on small integers. `kernels::ConvDims` holds the shape as `Conv2dGeom` does. The GEMM's store is now its own file, `gemm_store.wgsl`, so a kernel can replace it as it replaces the loaders.
- `kernels::ConvInputGrad`: the 2-D convolution's input gradient on the GPU, NCHW, with stride, padding and dilation, for a batch of images in one dispatch. It is an implicit GEMM through the tiled GEMM's core: each input value gathers the output gradients of the windows whose taps land on it, in the CPU reference's order (output channel, then kernel row, then column), so there is no scatter and nothing needs atomics. It is within `2(k + 3) · u · Σ|w·dy|` of `conv2d_backward_reference`'s input gradient in f64, `k` = out·kh·kw, and exact on small integers, checked on an Apple M4 (Metal) over the forward pass's shapes.
- `kernels::ElementwiseKernels`: the element-wise GPU kernels, each prepared once on given buffers (`call`) and added to a step (`record`), over any length (split over two dimensions above 65,535 workgroups). Add, multiply, scale, ReLU and leaky ReLU forward and backward, and dropout with a bit-packed mask (scale `1/(1 − p)` rounded in f32 on the host) are one rounding each and give the CPU's bits, NaN, ±0 and ±∞ included; NaN is tested by its bits. tanh and the sigmoid are the CPU kernels' formulas ported operation for operation (one exponential from the Cephes polynomial, a polynomial for tanh near 0), and GELU's tanh and erf forms (musl's erf with WGSL's exp) follow; forward and backward, they are within 4 ulp (tanh, sigmoid) or `4–8 · u` times the size of their terms (GELU) of the f64 tape on Vulkan, DX12 with DXC and with FXC.
- `kernels::BiasAdd` and `kernels::ChannelSums` work per channel on `[outer][channels][inner]` tensors (`ChannelDims`: an `M × N` matrix is `rows(m, n)`, an NCHW batch is `(batch, channels, h·w)`), with calls prepared once as the GEMM's are. `BiasAdd` adds a bias per channel in place, one addition per value, so on normal values it gives the CPU's bits (checked against `Tape::add`). `ChannelSums` sums each channel's `L = outer · inner` values in a fixed tree: a first pass sums chunks of 4,096 values per workgroup, each lane in order and then a halving tree, and a second pass adds each channel's chunks in order, with no atomics, so the bits are the same on every run. Against the exact sum each channel is within `2(L + 2) · 2⁻²⁴ · Σ|x| + (2L − 1) · 2⁻¹²⁶`, the last term for flushed subnormals; both kernels only add, so no bound depends on fused multiply-adds. Checked on an Apple M4 (Metal), exactly on integers whose partial sums stay below 2²⁴ and within the bound on seeded values, up to the CIFAR network's 131,072 values per channel.
- `kernels::BatchNorm2d`: 2-D batch normalisation on NCHW tensors, as `Tape::batch_norm2d` computes it.
  - **Forward:** the statistics come from the batch or from the running mean and variance. A batch's come from fixed trees: the sum, then the centred squares around the mean (never `E[x²] − E[x]²`), so they are the same on every run. They are kept as `[mean | 1/√(var + eps) | unbiased variance]`, then normalised with an optional affine `γ`, `β`.
  - **Backward:** `dβ = Σ dy`, `dγ = Σ dy·x̂`, and the closed-form input gradient through either kind of statistics. Every gradient is overwritten.
  - **Running update:** a momentum, or a cumulative average over the batch count, with the rates rounded as the CPU rounds them on `f32`. The count is kept on the host and advanced only for a step that ran (`RunningUpdate::commit`). The update is skipped on the GPU when the step's finite flag is set.
  - **Bounds:** each kernel's bound assumes every multiply-add may round twice, and WGSL's division (2.5 ulp) and `inverseSqrt` (2 ulp). A non-zero eps that is subnormal in f32, which the GPU would flush, is refused.
  - **Checks:** against the tape on an `f64` store end to end, and bit for bit on integers for the four sums, on an Apple M4 (Metal). Shapes run up to the CIFAR network's `(128, 32, 1024)`.
  - **Also:** `ChannelSums::call` takes an `accumulate` flag, which adds the sums to the output instead of overwriting it, for a gradient with several sources. Its uniform is now 32 bytes.
- The losses and the health values a training step reads back, on the GPU.
  - **Losses:** `kernels::SoftmaxCrossEntropy` (integer labels, the mean over the batch) and `kernels::MeanSquaredError` (the mean over every value), as the tape computes them with `Reduction::Mean`, with their gradients. Each writes its loss as one `f32` word at a word offset of an output buffer, so a step's results pack into one small readback.
  - **Cross-entropy bounds:** they allow WGSL's `exp` (3 + 2|x| ulp) and `log`, and subtractions in either order. A row with a NaN or infinite logit, or a label not below the classes, gives NaN.
  - **MSE:** the gradient is the CPU's bits on normal values.
  - **`kernels::SumSquares`:** each gradient tensor's sum of squares in a flat gradient buffer, one word each, for the gradient-norm checks.
  - **`kernels::FiniteFlag`:** the step's finite flag, a `u32` at word 0 of its own buffer that the optimiser and the running statistics read. It is set when the loss or any gradient value is NaN or infinite, tested by bits, so a gradient whose sum of squares overflows leaves it clear.
  - **`kernels::DeadRelu`:** one "ever non-zero" bit per neuron, or per channel after a convolution, OR-ed into a buffer that lasts through an epoch.
  - **Checks:** exact against the CPU's rules for the flag and the bits; within the bound of a sum for the sums of squares; against the tape for the losses, on an Apple M4 (Metal).

### Layers, training and inference (`cavitation-nn`)

- The dead-ReLU report counts by channel through a pooling layer too: in `Conv2d → MaxPool2d → ReLU` (or an average pooling there), a channel is reported dead only when every pooled position of it is, as it already was with batch norm or other element-wise layers in between. Before, such a ReLU fell back to counting each position, so the flat positions of a live channel came back as dead (#222).
- Channel masks for convolutions: `Sequential::channel_layer` names the layer that holds a `Conv2d`'s channels as the next layer receives them (the end of the run of `BatchNorm2d`, poolings and element-wise layers after it), `Sequential::set_channel_mask` switches whole output channels off there, as a mask that repeats each channel's bit over its positions, and `Sequential::channel_mask` reads it back per channel. An off channel sends 0 at every position, after batch norm (whose output at 0 is β) and the activations. The first step of shrinking CNNs by channel (#209).
- `shrink::channel_activity` measures each output channel of chosen `Conv2d` layers over a data set (mean, mean absolute value, firing share and maximum over its positions and the rows, read at `channel_layer`), and `shrink::ablate_channels` switches each channel off in turn and ranks them by what each one's absence costs, as `activity` and `ablate` do for neurons. `Evaluator::set_mask` changes the mask on any layer's output between evaluations, the route for channel masks (#209).
- `shrink::compact` compacts image models by channel: each output channel a channel mask switches off is removed from its `Conv2d`, from the `BatchNorm2d` and poolings of its run, and from the next `Conv2d`'s input channels or the channel's block of inputs of the `Linear` after a `Flatten`, and the compacted model matches the masked one within the rounding of the shorter sums. In the same pass it removes the off neurons of the model's `Linear` layers (a shrunk dense head after a `Flatten`), with the next `Linear`'s columns and a per-neuron `Prelu`'s slopes, as in a dense network. Before, `compact` refused any model with an image layer (#209).
- `shrink::shrink` shrinks `Conv2d` layers by output channel beside hidden `Linear` layers by neuron: by default every hidden `Linear` and every `Conv2d` whose channels reach a `Conv2d` or a `Linear`. Each step measures the convs with `channel_activity`, ranks their channels (`Ranking::OutNorm` takes a channel's input-channel weights in the next conv, or its block of columns in the `Linear` after a `Flatten`), switches the lowest off with `set_channel_mask`, retrains and measures; `ShrinkStep::kept` counts channels for a conv, and the parameter count is the compacted network's. With `fold_means`, a removed channel's mean goes into the next conv's bias (a conv without padding) or, position by position, into the bias of the `Linear` after a `Flatten` (#273). `train_found_size` rebuilds a shrunk CNN with new starting values (convs as `Conv2d::new` draws them, batch norms started again). `activity`, `ablate`, `shrink` and `train_found_size` no longer refuse a model with an image layer: its `Linear` layers are measured and shrunk as in a dense network (#209).

- `OptimizerConfig` has two new variants, `RmsProp` and `Adagrad`, and is now `#[non_exhaustive]`: a `match` on it outside `cavitation-nn` needs a wildcard arm (which also covers later variants). Building a value works as before.
- `shrink::ShrinkConfig` and `shrink::Ranking` take a lifetime parameter, and `ShrinkConfig::on_step` and `Ranking::Custom` are `Box<dyn FnMut(..) + Send + 's>`; `cavitation_inspect::ExploreConfig` takes one too, and its `shrink` factory is `Send + 's`. As for `FitConfig`, a callback can borrow local state (an `on_step` can push onto a `Vec` the caller reads after the run, without `Rc<RefCell<..>>`), and a configuration can move to another thread. A callback that captures something that is not `Send` (an `Rc`, a `Cell`) no longer compiles; borrow the value instead, or use `Arc` and an atomic or a `Mutex`. A function with no reference arguments returning one writes `ShrinkConfig<'static>`.
- `Init` has a new variant, `Normal { std }`, and is now `#[non_exhaustive]`: a `match` on it outside `cavitation-nn` needs a wildcard arm (which also covers later variants). Building a value, such as `Init::HeUniform`, works as before.
- `EpochReport` is `#[non_exhaustive]`, so a field added later is not a breaking change. Code outside `cavitation-nn` that builds one with a struct literal (to test a `StepControl`, say) uses `EpochReport::new(epoch, mean_loss, rows, seconds)`, which leaves `validation` as `None`. Reading the fields works as before; a struct pattern on it needs `..`.
- `LrSchedule::learning_rate` takes the step and the steps per epoch: `learning_rate(initial, step, steps_per_epoch, epochs)`. For the per-epoch schedules, epoch `e` is any step from `e · steps_per_epoch` to the end of that epoch, so the old `learning_rate(initial, e, epochs)` is `learning_rate(initial, e, 1, epochs)`. `LrSchedule` is `#[non_exhaustive]`: a `match` on it outside `cavitation-nn` needs a wildcard arm.
- `Health`, `HealthMonitor`, `Trainer`, `FitConfig`, `shrink::FromScratch` and `cavitation_ml::GradientConfig` take a lifetime parameter, and `Health::sink` and `FitConfig::on_epoch` are `Box<dyn FnMut(..) + Send + 's>`. The callbacks can borrow local state (a sink can push onto a `Vec` the caller reads after the run, without `Rc<RefCell<..>>`), and a `FitConfig` or a `Trainer` can be moved to another thread. A callback that captures something that is not `Send` (an `Rc`, a `Cell`) no longer compiles; borrow the value instead, or use `Arc` and an atomic or a `Mutex`. Code that names one of these types where a lifetime cannot be elided, such as a function with no reference arguments returning `FitConfig`, writes `FitConfig<'static>`; `TrainerHandle` and every `StepControl` are unchanged.
- `FitConfig` has a new field, `dropout_seed` (default 0). A `FitConfig` built with a struct literal that lists every field needs it added; one built with `..FitConfig::default()` does not.
- `InferenceLayer` has a new variant, `Identity`, and is now `#[non_exhaustive]`: a `match` on it outside `cavitation-nn` needs a wildcard arm (which also covers the image layers' forms to come).
- `FitConfig` has a new field, `early_stopping` (default `None`), and `History` two, `best_epoch` and `stopped_early`. A struct literal that lists every field needs them added; one built with `..FitConfig::default()` or `..History::default()` does not.

### Tensors and autograd (`cavitation-core`)

- The GEMM's per-thread packing buffers are reserved on a thread's first call for the largest block its kernel ever packs, so a thread that later meets a larger product (a convolution group can run on any worker) does not grow them; before, such a thread allocated once more after warm-up. Each thread that runs a GEMM holds about 2 MB for `B` and 98 KB (AVX2) to 393 KB (SSE4.2) per slot for `A`.
- Training tapes: `Graph::training_tape(values, seed, step)` opens a tape for a training step, and `Tape::is_training` tells a layer which kind it is recording on, so a layer such as dropout can act one way in training and another in evaluation. `Graph::tape` opens an evaluation tape, as before. `Tape::stream_seed(stream)` gives each random stream on a training tape a seed from the tape's seed, its step and the stream id, the same on every machine and for any thread count. `Trainer` and `fit` record each step on a training tape seeded by `Trainer::set_dropout_seed` (`FitConfig::dropout_seed`) and the step's number; evaluation, validation, the shrink tools and the inspector's probe record on evaluation tapes.
- Dropout on the tape: `Tape::dropout(x, p, stream)` is inverted dropout as in PyTorch (each value kept with probability `1 - p` and scaled by `1 / (1 - p)`) on a training tape, with its mask drawn from `Tape::stream_seed(stream)`, and returns `x` itself on an evaluation tape. `Tape::dropout_with_mask(x, keep, p)` takes the mask, so a mask drawn elsewhere can be reproduced; it matches PyTorch's dropout with the same mask, value and gradient. `Tape::next_stream` hands out stream ids in call order, so a layer's draws do not move when hooks or masks record extra nodes.
- 2-D convolution on the tape: `Tape::conv2d(x, weight, bias, geom)` computes PyTorch's `nn.Conv2d` (`groups = 1`, zero padding) on images stored as flat rows in NCHW order, with `Conv2dGeom` giving the channels, image and kernel sizes, stride, padding and dilation (checked when it is made, so every image has an output). The batch is cut into at most 16 groups of consecutive images (`kernels::conv::groups`), which run in parallel on the thread pool when there are at least as many groups as threads (a smaller batch runs its groups one at a time, each GEMM on every thread): each group copies its images' windows into column matrices (`kernels::conv::im2col`, about 2 MB at a time) and multiplies them by the weight with the GEMM of the current kernel level; the weight gradient adds one partial per group in group order, so results are the same for any thread count. A 1 × 1 kernel with stride 1 multiplies each image itself. `kernels::conv::conv2d_forward` and `conv2d_backward` are the passes the tape and `InferenceModel` share. `kernels::conv::conv2d_reference` and `conv2d_backward_reference` are the direct loops it is tested against, and it matches PyTorch's `F.conv2d` and its gradients.
- 2-D pooling on the tape, on the same flat NCHW rows: `Tape::max_pool2d` (PyTorch's CPU rule: a tie goes to the first value in row-major order, a NaN wins, the last of several, padding never wins; the gradient goes to each window's winner), `Tape::avg_pool2d` (`count_include_pad`, a divisor override, and under `ceil_mode` the padding counted but not the overhang) and `Tape::adaptive_avg_pool2d` (PyTorch's windows, global average pooling at output `(1, 1)`), with `Pool2dGeom` giving the channels, image and window sizes, stride, padding (at most half the window, as PyTorch requires), dilation and `ceil_mode`, and refusing a dilated geometry in which some window holds no pixel of the image. The loops in `kernels::pooling` are the implementation and the reference; they match PyTorch's pooling functions and gradients.
- 2-D batch normalisation on the tape: `Tape::batch_norm2d(x, weight, bias, running, channels, spatial, eps)` follows PyTorch's `BatchNorm2d`: batch statistics (biased variance) on a training tape or without running statistics, the `RunningStats` (mean, variance, optional batch count and momentum, `None` for the cumulative average) on an evaluation tape, read without being recorded so they never take a gradient. A training tape records each batch's mean and unbiased variance, and `Graph::apply_buffer_updates` moves the running statistics towards them once the tape is dropped, as PyTorch updates them. It matches PyTorch's training-mode `batch_norm` and its gradients.
- SiLU and the tanh form of GELU run in f32 on the sigmoid and tanh SIMD kernels, on the tape (`Tape::silu`, `Tape::gelu` with `GeluApprox::Tanh`), in the `Silu` and `Gelu` layers' `Activation::f` and in `InferenceModel`, which agree bit for bit: `kernels::activation::silu_f32` (within 7 ulp of the correctly rounded value while the sigmoid is a normal number) and `gelu_tanh_f32` (within `|x| · 2⁻²¹` plus 2 ulp of the f64 value), with `_with` forms taking the level, and `Real::silu_in_place` and `Real::gelu_tanh_in_place`. Measured with `cavitation-bench activation` over 4,096 values on an Intel Celeron N5105, pinned to one core of a machine with a load average of about 2.4: SiLU 14.04 ns per value with the scalar loop, 5.52 at `sse4.2` (2.5x); GELU's tanh form 34.24 ns, 7.42 at `sse4.2` (4.6x). f64 values are unchanged.
- The GLU's sigmoid, SiLU and tanh-GELU gates run on the same kernels, on the tape (`Tape::glu`) and in `InferenceModel`, which still agree bit for bit: each row's gate half goes through the kernel at once instead of one scalar value at a time. The gate values change in the last bits, within the kernels' bounds; the exact-GELU and ReLU gates are unchanged.
- `kernels::activation::softplus_f32` and `elu_f32(alpha, ..)`, with `_with` forms taking the level: softplus as `max(x, 0) + ln(1 + e^(−|x|))` and ELU's `e^x − 1` so that it keeps its relative accuracy near 0, on the exponential `tanh` and the sigmoid use and a new `log1p` on `(0, 1]`. Over every finite f32, softplus is within 2 ulp and `e^x − 1` within 1 ulp of the correctly rounded result. SSE4.2 runs them four lanes at a time with the reference loop's bits (softplus four vectors side by side, which on an Intel Celeron N5105 takes about half the time of one vector at a time), AVX2 eight lanes and NEON (and Accelerate) four lanes at a time with fused multiply-adds, within one ulp more (3 and 2 ulp, checked on a sweep of one f32 in 1,009 and the edge values). ELU keeps the sign of `−0` and is `alpha · x` for inputs under `2⁻²⁵` in size.
- Softplus, log-sigmoid, Mish, ELU, SELU and CELU run in f32 on those kernels, on the tape (`Tape::softplus`, `log_sigmoid`, `mish`, `elu`, `selu`, `celu`), in the layers' `Activation::f` and in `InferenceModel`, which agree bit for bit: `kernels::activation::softplus_beta_f32` (any `beta` and threshold), `log_sigmoid_f32`, `mish_f32` (softplus then tanh on blocks of 64 values), `selu_f32` and `celu_f32`, with `_with` forms taking the level, and the matching `Real` methods (`softplus_in_place`, `log_sigmoid_in_place`, `mish_in_place`, `elu_in_place`, `selu_in_place`, `celu_in_place`). Values change in the last bits, within the bounds each function's docs state; f64 values and every derivative are unchanged. Measured with `cavitation-bench activation` over 4,096 values on an Intel Celeron N5105, pinned to one core of a machine with a load average of about 2.2, in ns per value, the scalar loop then `sse4.2`: softplus 25.68 → 9.09 (2.8x), log-sigmoid 24.12 → 7.95 (3.0x), Mish 72.61 → 16.28 (4.5x), ELU 11.62 → 5.26 (2.2x), SELU 12.73 → 5.36 (2.4x), CELU 12.67 → 6.30 (2.0x).
- The SSE4.2 `tanh`, sigmoid and ELU kernels also run four vectors side by side, with the same bits. Measured with `cavitation-bench activation` over 4,096 values on an Intel Celeron N5105, pinned to one core, in ns per value before and after: `tanh` 6.76 → 5.24, sigmoid 4.95 → 4.07, SiLU 5.51 → 4.73, GELU's tanh form 7.39 → 5.86, ELU 5.26 → 3.51, SELU 5.36 → 3.60, CELU 6.30 → 4.57, Mish 16.28 → 14.79.
- `Real::relu`, the ReLU every part of the library computes (0 at or below 0, so `-0` becomes `+0`; NaN stays NaN), replaces three private copies in the tape, the matvec kernel and inference. The `Real` doc examples call the trait's methods (`Real::exp(x)`) instead of the inherent `f32` and `f64` ones, so they test the trait.
- `Tensor::clone_from` and `ParamValues::clone_from` copy into the buffers the target already has when they are large enough, so copying the values of the same parameters again allocates nothing; before, they allocated a fresh copy as `clone` does.
- `Tensor::into_vec` gives up a tensor and returns its elements without copying them, so a tensor can grow in place through `from_vec`.
- When the thread pool cannot start a worker thread, it frees the memory it had set aside for that worker instead of keeping it for the rest of the process.
- `kernels::Level::ALL` lists every kernel level, in the order of their numbers, supported on this CPU or not (a slice, so a later level can be added without changing its type).
- `Tape::glu`, `softmax` and `log_softmax` on an input whose last axis has width 0, and `softmax_cross_entropy` and `nll` with no classes, now mark a parameter's gradient current in the backward pass, as every other operation does; it was left stale.

### Layers, training and inference (`cavitation-nn`)

- Early stopping and plateaus in `fit`: `FitConfig::early_stopping` (`EarlyStopping`) ends a run after `patience` epochs in a row in which a `Monitor` (the training loss, the validation loss, or the validation accuracy or R²) did not improve by more than `min_delta`, and by default ends it with the best epoch's parameters and buffers, also when the run reaches its last epoch; `History::best_epoch` and `History::stopped_early` say what happened. `LrSchedule::ReduceOnPlateau` is PyTorch's `ReduceLROnPlateau` stepped after each epoch (factor, patience, `Threshold::Relative` or `Threshold::Absolute`, cooldown, minimum rate), and gives PyTorch's rates bit for bit for the same measures (`scripts/fixtures/reduce_on_plateau.py`); `LrSchedule::reduce_on_plateau` takes PyTorch's defaults. `cavitation_ml::GradientConfig` refuses the plateau schedule with `Error::Unsupported`, as its loop makes no per-epoch measures. Copying the best parameters allocates once; a `no_alloc` scenario checks that later epochs, the plateau steps and the final restore allocate nothing. Bad settings, or a validation measure without a validation set, are `InvalidData` before the first step.
- The vanishing-gradient warning on a bias adds that a batch norm right after its layer cancels the bias, and to build that layer without one: the bias's gradient is then rounding noise, and the warning's other hints (a deep network, saturating activations) do not apply.
- The shrink tools (`activity`, `ablate`, `compact`, `shrink`, `train_found_size`) refuse a model with an image layer (`Conv2d`, `BatchNorm2d`, `MaxPool2d`, `AvgPool2d`, `AdaptiveAvgPool2d`) with `Error::Unsupported` naming the layer, before doing anything; they work on the neurons of dense networks.
- The dead-ReLU report reads a ReLU after a `Conv2d` or `BatchNorm2d` (through element-wise layers) by channel: a position counts as dead only when its whole channel output 0 for every sample of the epoch. Before, each position was a neuron of its own, and a live channel's positions that see only flat input, such as an image's blank border, were reported dead. `Warning::DeadNeurons` still lists positions, now the positions of dead channels. The steering recipe and the `mnist_cnn` example keep the report on.
- `Dropout`, PyTorch's `nn.Dropout`: random masks while training, seeded by `FitConfig::dropout_seed`, the step and the order of the dropout layers on the tape, so a run gives the same masks on every machine and for any thread count; it passes its input through in evaluation and at inference. `Dropout::new` refuses a drop probability outside `[0, 1)`.
- `Flatten` and `Identity`, PyTorch's `nn.Flatten` and `nn.Identity`, which pass their input through, so a PyTorch `nn.Sequential` that uses them keeps its layer numbers and its state dict loads by key.
- `Conv2d`, PyTorch's `nn.Conv2d` (`groups = 1`, zero padding) on images stored as flat rows in NCHW order: weight `[out, in, kh, kw]` and bias `[out]` under PyTorch's names, PyTorch's default initialisation (`Conv2d::new`) or any `Init` with the convolution's fans (`Conv2d::with_init`, which also makes a layer without a bias). `InferenceModel` runs it through the same column matrices and GEMM as the tape, giving the tape's bits, allocates nothing per call after the first, and `refresh_in_place` copies new weights into it. `as_conv2d` on `dyn Layer` finds one, as `as_linear` does a `Linear`.
- The `cavitation` prelude exports the image layers and their geometries: `Conv2d`, `Conv2dGeom`, `MaxPool2d`, `AvgPool2d`, `AdaptiveAvgPool2d`, `Pool2dGeom`, `BatchNorm2d`, `Dropout`, `Flatten` and `Identity`.
- `Init::TorchDefault`, uniform in `±1 / sqrt(fan_in)`: PyTorch's default for the weights and biases of `nn.Linear` and `nn.Conv2d`.
- `MaxPool2d`, `AvgPool2d` and `AdaptiveAvgPool2d`, PyTorch's layers of the same names on flat NCHW rows, with inference forms that run the tape's loops (so `InferenceModel` gives the tape's bits).
- `AdaptiveAvgPool2d::new` returns `Error::InvalidData` when `channels · height · width` of its input or output overflows `usize`; `Tape::adaptive_avg_pool2d` panics naming the sizes, and `InferenceModel::compile` refuses such a form, instead of the size wrapping in a release build.
- `BatchNorm2d`, PyTorch's `nn.BatchNorm2d` (`eps`, momentum or the cumulative average, `affine`, `track_running_stats`): batch statistics while training, running statistics in evaluation and in `InferenceModel` (which gives the tape's bits). `Trainer` and `fit` apply its running-statistics updates after each kept step; a skipped step leaves them too. Its `running_mean`, `running_var` and `num_batches_tracked` are buffers (`Layer::buffers`, `Sequential::state_names`) that `save` and `load` carry under PyTorch's names, the batch count as an `I64` scalar as PyTorch stores it; a file without the count loads with 0. `dyn Layer::as_batch_norm2d` finds one in a model. Refreshing a compiled model (each epoch's validation in `fit`) copies new running statistics, γ and β into its batch norm in place, allocating nothing. The manual training loop calls `Graph::apply_buffer_updates` after the optimiser's step (README and guide).
- `RmsProp` and `Adagrad` optimisers with `torch.optim.RMSprop` (α, eps, momentum, weight decay, and centred with `with_centered`) and `torch.optim.Adagrad` (rate decay, weight decay, initial accumulator, eps) semantics, each with a plain reference loop and a chunked loop on the thread pool that agree bit for bit, and ten-step PyTorch fixtures they match within `1e-6 + 1e-5·|torch|` on both update paths. `OptimizerConfig::RmsProp` and `OptimizerConfig::Adagrad` build them in `fit`; both are in the `cavitation` prelude.
- `inspect_file(path)` lists every tensor of a safetensors file with its name, element type and shape (`TensorInfo`), in the file's data order, without a model: what a file holds when a `load` fails. It checks the file as `load` does, with the same `torch.save` advice. Both are in the `cavitation` prelude.
- The end-of-epoch dead-neuron report reuses one list of dead neurons, lent to each `Warning::DeadNeurons` and taken back after it is sent, so a long `fit` whose report fires every epoch no longer allocates after warm-up (a `no_alloc` scenario checks it: 24 allocations over epochs 3–6 before, 0 now).
- `Layer::local_derivative`'s default and `Prelu`'s panic, naming both lengths, when `out` does not hold one value per input value, instead of filling only the shorter of the two. The `HookId` docs say that an id belongs to the `Hooks` that made it.
- `Evaluator::refresh` on a model that runs on the tape (one with a layer of your own that has no inference form) copies the new parameter values into the evaluator's own in place when the model has the same layers as before, as on the compiled engine, so `fit`'s validation set allocates nothing from the second epoch on for such a model as well.
- Learning-rate schedules by step, with a linear warm-up: `LrSchedule::Warmup { steps }` climbs linearly to the optimiser's rate over the first `steps` steps (step `s` trains at `lr · (s + 1) / steps`) and then holds it, and `LrSchedule::WarmupCosine { warmup_steps, min_lr }` follows the warm-up with cosine annealing by step over the rest of the run (with `warmup_steps: 0`, PyTorch's `CosineAnnealingLR` stepped after every batch). `fit`, `fit_controlled` and `cavitation_ml`'s gradient path set their rate before every step; a run under one trains to the same parameters as a manual loop of `Trainer::step` calls at the same rates, bit for bit. `Constant` and `Cosine` still set the rate once per epoch.
- `Init::Normal { std }`: normal starting values with mean 0 and the given standard deviation, whatever the fans (PyTorch's `normal_(0, std)`, for recipes that say `std = 0.02`). A negative or non-finite deviation panics.
- `Dataset::extend` appends another data set's rows and targets after the existing ones without copying those, so collecting data in rounds costs time in proportion to the rows added. It panics, leaving the data unchanged, when the feature counts, the target kinds or the output counts differ.
- `save` records the model's layer kinds (`linear,relu,linear`) under `cavitation.layers` in the file's `__metadata__`, and `load` (and `load_with` with `strict` and no `rename`) returns `Error::Format` listing both when a file records other kinds: GELU-trained weights no longer load silently into a ReLU network (where the digits test set scored 339 of 360 instead of 345). Files without the record, PyTorch's among them, load as before; PyTorch ignores the metadata.
- `load`, `load_lenient` and `load_with` read `F16`, `BF16` and `F64` safetensors files as well as `F32` ones: half precision widens to `F32` exactly (subnormals, infinities and NaN payloads included), and `F64` rounds to the nearest `F32`, as PyTorch's `.float()` does, with a finite value beyond the `F32` range refused as `Error::Format` naming its key. Checked bit for bit against state dicts written by PyTorch in each type. `save` still writes `F32`.
- `StepLog`, a `StepControl` for `fit_controlled` that keeps one `StepRecord` per training step: its number, epoch, loss, rows and wall-clock seconds, and with `StepLog::with_update_times` the optimiser's update time from the step's profile (every step after the first recorded one is then profiled). `reserve` sizes its list once. A run without it is unchanged. Both are in the `cavitation` prelude.
- `shrink::ablate` (and `ablate_with`, `ablate_controlled`) runs the layers before each swept `Linear` once, keeping that `Linear`'s input for every row, and then only the layers from the `Linear` on for each of its neurons; the results are bit-identical. Sweeping the second hidden `Linear` of a 64 → 256 → 256 → 10 network over 1,000 rows: 2.67–2.78 s before, 2.22 s after (one thread pinned to one core, on an Intel Celeron N5105 at kernel level `sse4.2`). The gain grows with the share of the work before the swept layer; the first `Linear`'s input is the data, so its sweep is unchanged. The kept input takes `rows × width` values for the swept layer's input width.

### Breaking changes

- `EpochReport` has a new public field, `rows`, so code that builds an `EpochReport` with a struct literal must set it.
- `EpochReport` has a new public field, `validation: Option<Evaluation>`, so code that builds an `EpochReport` with a struct literal must set it (`validation: None`).
- `FitConfig` has a new public field, `validation: Option<Dataset>`. A struct literal that ends with `..FitConfig::default()` needs no change (the default is `None`); one that lists every field must add `validation: None`.
- `shrink::ShrinkConfig` has a new public field, `fold_means`, so code that builds a `ShrinkConfig` with a struct literal and no `..ShrinkConfig::default()` must set it.
- `OnNonFinite` has a new variant, `Skip`, and is now `#[non_exhaustive]`: a `match` on it outside `cavitation-nn` needs a wildcard arm (which also covers later variants). Building a value, such as `OnNonFinite::Stop`, works as before.
- `Linear::bias` returns `Option<ParamId>`, `None` for a layer without a bias. A layer from `Linear::new`, `with_init` or `from_values` always has one, so `layer.bias().unwrap()` is the old value.
- `InferenceLayer::Linear`'s `bias` field is `Option<Vec<f32>>`, `None` for a layer without a bias. A layer of your own that returns this form from `Layer::inference` builds it with `bias: Some(values)` (or `None` for no bias), and code that reads the field uses `bias.as_deref()`, which gives an `Option<&[f32]>`.

### Workspace

- The `cavitation` crate has two features: `ml` (on by default) re-exports `cavitation-ml` as `cavitation::cavitation_ml`, and `inspect` (off by default) re-exports `cavitation-inspect` as `cavitation::cavitation_inspect`. `default-features = false` leaves both out. `cavitation::prelude` adds `LinearRegression`, `LogisticRegression`, `LinearModel` and `LogisticModel` with `ml`, `Inspector` and `InspectorConfig` with `inspect`, and `Standardizer`, `Flow`, `fit_controlled`, `StepControl`, `StepInfo`, `StepProfile`, `ModelHandle` and `TrainerHandle` always.
- Doc comments are wrapped at 100 columns.

### Tensors and autograd (`cavitation-core`)

- New error variant, `Error::Net`, for an address the inspector cannot listen on. `Error` is `#[non_exhaustive]`, so this is not a breaking change.
- `Tape::backward_timed`: `backward` with bit-identical gradients that also adds the time between marks (each layer's output, say) to the caller's `times`, reading the clock only at the marks.
- `ParamGrads::like` makes a second gradient set for a store, allocated on first use, so a second backward pass leaves `ParamStore::grads` untouched; `ParamGrads::zero_grad` clears it.
- SIMD `tanh` and sigmoid for f32: `kernels::activation::tanh_f32` and `sigmoid_f32` (and `_with` variants that take a `Level`), with SSE4.2, AVX2 and NEON kernels and the scalar twins `kernels::reference::tanh_f32` and `sigmoid_f32`. Results are within 3 ulp of the correctly rounded value at every level (2 ulp at the reference and SSE4.2 levels, checked for every finite f32); the SSE4.2 kernel matches the reference bit for bit; a value's result does not depend on where it sits in the slice. `Tape::tanh` and `Tape::sigmoid` in f32 run them, as do the new `Real::tanh_in_place` and `Real::sigmoid_in_place` (`Real` is sealed, so adding methods breaks no code). f32 results change in the last bits; f64 is unchanged. On an Intel Celeron N5105 at SSE4.2, over 4,096 values, measured with `cavitation-bench activation` pinned to one core while the machine was busy (load average 5): tanh 7.3 ns per value against 29.7 ns for the scalar `f32::tanh` loop (4.1x), sigmoid 5.4 ns against 14.5 ns (2.7x).
- The backward pass of `Tape::binary_cross_entropy` with both inputs taking a gradient computes each element's logarithms once instead of twice, with the same gradients bit for bit: 3.29 ms before, 2.43 after for 65,536 values (forward and backward, one thread pinned to one core, on an Intel Celeron N5105 at kernel level `sse4.2`, load average about 2.5). The other two-input losses, `kl_div` included, are unchanged: their two gradients share no costly work, and the one-pass form measured no faster for `kl_div`.

### Classic machine learning (`cavitation-ml`)

- A new crate for classic models in `f64`, with no dependency outside the workspace.
- Least squares: `linalg::lstsq` and `linalg::Qr`, a Householder QR that scales columns by powers of two (so columns from about 1e-300 to 1e300 factor correctly) and names the first column that depends on the ones before it; `linalg::qr_reference` is its plain twin.
- `LinearRegression` (ordinary least squares, and ridge with `alpha > 0`): `fit` solves exactly by QR and matches scikit-learn's `LinearRegression` and `Ridge` within 1e-9; `fit_gradient` trains one `Linear` with a `GradientConfig` (by default 1,000 full-batch epochs of Adam with cosine decay). Both return a `LinearModel` with `predict`, `score` (R²), `to_sequential` (saves as a PyTorch `nn.Linear`) and `from_sequential`.
- `LogisticRegression` (scikit-learn's defaults: an intercept and `c = Some(1.0)`): `fit` solves two classes exactly by Newton's method, matching scikit-learn's `newton-cholesky` within 1e-8 and `lbfgs` within 1e-5; `fit_gradient` handles two or more classes. Separable classes without a penalty, a single class, and labels other than 0 and 1 are `Error::InvalidData`, each message suggesting what to change. Both return a `LogisticModel` with `predict_proba`, `predict`, `score` (accuracy), `objective` and `to_sequential`.
- `LinearModel::from_sequential` reads a `Linear` without a bias as a model whose intercept is 0 for every output.
- `fit_gradient` honours `OnNonFinite::Skip` in `GradientConfig::health`: a skipped step changes nothing and counts toward neither `mean_loss` nor `rows`, and an epoch in which every step was skipped ends the fit with `Error::NonFinite`.

### Inspector (`cavitation-inspect`)

- A new crate, built on `std::net` alone: `Inspector::start(InspectorConfig)` serves a live view of training to the browser on `127.0.0.1:7878` by default, and `Inspector::url` gives the address with a per-run 128-bit token. The server refuses requests without the token, with a `Host` other than its own address or with a foreign `Origin`; it never sends `Access-Control-Allow-Origin`, and GET changes nothing. Every connection has a read and a write timeout, and dropping the `Inspector` first gives clients up to 500 ms to read what is queued, then stops every thread within 1 s.
- `cavitation_inspect::fit` trains under the inspector. While a page is open it captures, at most `snapshot_hz` times a second (4 by default), the run's statistics, one probe row through every layer (a, z, f′(z), ∂L/∂a, ∂L/∂z), the chosen neuron and a per-layer step profile, and at epoch ends evaluates the model on the probe rows when the time since the last evaluation is at least `EVALUATION_FACTOR` (200) times its cost, at most about 0.5% of the run (always after the last epoch); when training ends with a page open, one last snapshot shows the final step and epoch. The page can switch neurons, override the learning rate, pause and resume, and pick the probe row and neuron; every command is checked. With no page open nothing is captured, and a run with no commands trains to the parameters of `fit`, bit for bit.
- The page: one self-contained HTML file built into the crate, with a strict Content Security Policy and no request outside its own server. It shows the run's figures, every layer as a heat map, the chosen neuron with the chain rule and its activation curve, the step profile, and the shrink lab. `Inspector::export_html` and `GET /export` save it with the run so far embedded, to open without a server.
- Explore mode: `Inspector::explore` serves a trained network to the page, which can switch neurons, rank a hidden layer's neurons by ablation, and shrink the network level by level, with `Cancel` ending a run after the step in progress.
- The neuron panel shows a neuron of a `Linear` without a bias with no bias and its sum as `Σ w·x`; the `neuron` event has a new field, `has_bias`, and `bias` is `null` for such a neuron.
- `sse::Hub`, `json::JsonWriter` (NaN and infinity as `null`, `<`, `>`, `&`, U+2028 and U+2029 escaped), `commands`, `probe::Probe` and `wire` (every event's fields) are public for programs that build their own view.
- A snapshot (`stats`, `probe`, `neuron`, `profile`) is no longer sent ahead of an event that is still waiting for the hub: while a `status`, `epoch` or `model` event that the hub's lock refused waits, no snapshot is taken, so a page sees a paused run's `paused` status before its paused `stats`. A `profile` the hub's lock refused is asked for again on the next step instead of being lost. In explore mode, commands sent before a ranking or a shrink run starts are read before its first neuron or level, so a cancel sent early always stops the run at its first stopping point.

### Layers, training and inference (`cavitation-nn`)

- A `Linear` without a bias, like PyTorch's `nn.Linear(inputs, outputs, bias=False)`: `Linear::without_bias` (the weight drawn as `with_init` draws it) and `Linear::from_weight` make one. It computes `x · Wᵀ`, its only parameter is `weight`, so `save` writes `{i}.weight` alone and a PyTorch `state_dict` of a bias-free layer loads with `load`; it matches PyTorch's forward pass and gradients (a new fixture, written with torch 2.15.0 by `make_fixtures.py --only no-bias`). Compiled inference skips its bias add, `compact` and `train_found_size` keep the layer without a bias, and `Standardizer::fold_into_input` and `fold_into_output`, which must write a bias, refuse it with `Error::InvalidData`, as does `shrink` with `fold_means` when the `Linear` after a listed layer has no bias.
- `fit_controlled` runs a `StepControl` after every step and epoch. The control gets a `StepInfo`, a `ModelHandle` that can change only the neuron masks, the parameters to read, and a `TrainerHandle` that can only ask for a `StepProfile`, override or read the learning rate and read the step count; `Flow::Stop` ends the run. `fit` and `fit_with_hooks` run the same loop with no control.
- `Trainer::override_learning_rate`, `Trainer::learning_rate`, `Trainer::profile_next_step` and `Trainer::last_profile` (each layer's forward and backward time, the loss, the optimiser and the whole step; steps not profiled read no clock and allocate nothing), and `Trace::set_timing` and `Trace::forward_time`.
- `Standardizer`: each column's mean and population standard deviation, `transform` and `inverse_transform`, and `fold_into_input` and `fold_into_output`, which write the scaling into the first or last `Linear` so a trained network takes raw inputs or answers in the targets' units.
- `shrink::ablate_controlled`: `ablate_with` whose callback returns a `Flow`, so a sweep can stop early.
- `ShrinkConfig::fold_means` (off by default): `shrink` folds each removed neuron's mean output on the training rows into the next `Linear`'s bias before retraining, measured on the network with the step's earlier layers already shrunk; for a neuron whose output is constant the network's outputs do not change, within rounding. `shrink::train_found_size` trains a network of the size a shrunk network has from new starting values (`shrink::FromScratch`: the weight and bias `Init`, a seed and the `FitConfig` recipe) and returns both networks' measures on the rows you give, with the fresh network, in a `shrink::FoundSize`; the `shrink_digits` example's `--lottery` uses it.
- `Loss::record` is public, so a tape of your own can record the training loss.
- `InferenceModel` runs `Tanh` and `Sigmoid` layers through the SIMD activation kernels, and `Activation::f` of the built-in `Tanh` and `Sigmoid` gives the same bits as the tape and compiled inference. On an Intel Celeron N5105 at SSE4.2, one input through a 4 → 32 → tanh → 32 → tanh → 1 network takes 841 ns against 353 ns for the same network with ReLU, measured with `cavitation-bench activation` pinned to one core while the machine was busy.
- `FitConfig::validation`: a held-out set that `fit`, `fit_with_hooks` and `fit_controlled` measure after every whole epoch with the run's loss, recorded in `EpochReport::validation` (the loss, and the accuracy or R²) before `on_epoch` runs. It is bit for bit what `evaluate` gives on the parameters and neuron masks as the epoch left them, follows the masks a `StepControl` changes, and after the first epoch allocates nothing for a model that compiles. An unsuitable validation set is `Error::InvalidData` before training, with a message that starts with `validation: `. A control that stops the run mid-epoch leaves that epoch without a validation.
- `Evaluator::refresh` copies new weights and mask values in place without allocating when the model has the same layers, the masks sit where they did and no clone shares its weights (it used to allocate on every call).
- `OnNonFinite::Skip`: a step whose loss or gradient is NaN or infinite sends the warning and is left out, leaving the parameters and the optimiser's state (momentum, moments, Adam's step counts) as they were, and training continues; with the other batches unchanged and in the same order (for example `shuffle_seed: None`), a run that skips a step ends with the parameters, bit for bit, of the run without that step's batch. Only `Skip` reads every gradient once more per step, before the update; `Stop` and `Warn` do not. A skipped step counts in `Trainer::steps` and in the new `Trainer::skipped_steps` and `TrainerHandle::skipped_steps`, but not in `EpochReport::rows`, `mean_loss` or the loss the vanishing-gradient check compares against; hooks still run on it, `StepControl::after_step` does not, and a profile asked for carries over to the next step that trains. An epoch in which every step was left out ends the run with `Error::NonFinite` naming the epoch. A hand-written loop asks the new `HealthMonitor::before_update` whether to apply each update.
- The docs of `OnNonFinite::Warn` say what it does: the update is applied, so a NaN loss or gradient reaches the parameters and from the next step every parameter.
- The docs of `OnNonFinite::Stop` say that a NaN or infinite gradient with a finite loss is found after the update has applied it, so the parameters already hold the NaN when the error comes back; `Skip` keeps the last good values.
- `Adam` and `AdamW` fold the bias corrections into two scalars per step (`lr / (1 − β₁ᵗ)` and `1 / √(1 − β₂ᵗ)`), as `torch.optim.Adam` does, so each element takes one square root and one division instead of three divisions; results can differ from before in the last bit, and still match `torch.optim` over the ten-step fixtures. Update of one 1,068,810-element parameter on one thread: 14.06 ns per element before, 11.62 after (1.21x; `CAVITATION_THREADS=1 taskset -c 2 cavitation-bench subnormal --steps 700`, the Adam blocks of steps 1 to 700, median of 42 blocks per build, builds alternated, on an Intel Celeron N5105 at kernel level `sse4.2` while the machine was busy, load average 2.6 to 4.5).
- `Sgd`, `Adam` and `AdamW` hand the chunks of every parameter of a step to the thread pool in one call, instead of one call per parameter, so a network of small parameters uses every thread for its update. The chunks and the order of the statistics' sums are unchanged, so results are bit-identical to before, for any thread count. Update of the digits network's 50,826 parameters at 4 threads: Adam 387–393 µs before, 218–280 after; SGD with momentum 176–182 before, 95–102 after (measured on an Intel Celeron N5105 at kernel level `sse4.2` while the machine was busy, load average about 3, three interleaved runs of 101 rounds; at 1 thread both versions take the same time).
- `InferenceModel::infer_batch` (and `infer_batch_observed`) run a batch of one row through `infer`'s matvec path on the calling thread, giving `infer`'s output bit for bit; it was the GEMM's, which can differ in the last bits on some kernel levels. One row through a 4 → 32 → 32 → 1 tanh network: 3.76 µs before, 0.88 after, against 0.85 for `infer`; with ReLU 3.27 before, 0.38 after, against 0.35 (`CAVITATION_THREADS=1`, pinned to one core, on an Intel Celeron N5105 at kernel level `sse4.2`, load average about 2.5). New `InferenceModel::infer_rows(inputs, rows)` runs rows laid out in a plain `&[f32]`, without building a tensor, with `infer_batch`'s outputs.

### Layers, training and inference (`cavitation-nn`)

- `Sequential` is `Clone`: a clone shares its layers (they never change after `push`, so a user layer with interior mutability, such as a `Mutex` field, is shared between the copies, and a layer need not be `Clone`) and copies its neuron masks. Clone the `ParamStore` too for an independent network: training the clone then leaves the original's values unchanged.
- `Init` (Xavier and He initialisers, zeros, constant), the object-safe `Layer` trait, `Linear` (weight `[outputs, inputs]` like PyTorch), a layer for every built-in activation plus `Softmax`, `LogSoftmax`, `Glu` and `Prelu`, `Activation` and `ActivationLayer` for activations of your own, and `Sequential` with `Trace` and PyTorch-style parameter names (`0.weight`, `2.bias`). `Sequential` checks the width between layers and names the layer that does not fit.
- Optimisers: `Sgd` (momentum, weight decay), `Adam` and `AdamW`, matching `torch.optim` over ten-step trajectories. Each updates its parameters in chunks of 16,384 elements over the thread pool, bit-identical to the plain loop that runs at the reference level, and collects each gradient's norm and finiteness (`GradStats`) in the same pass. A parameter that received no gradient since `zero_grad` is skipped, as PyTorch skips `grad is None`; Adam's bias correction counts each parameter's own updates. Momentum buffers and Adam's moments store any value below the type's smallest normal number (`Real::MIN_POSITIVE`) as 0, so they never pass through the subnormal range, where updates ran 13.7 (momentum) and 7.4 (Adam) times slower (Adam update on decayed state 28.6 ms before, 3.9 ms after; measured with `cavitation-bench subnormal` on an Intel Celeron N5105); a value PyTorch would keep as a subnormal is 0 here. `Sgd::momentum`, `Adam::moments` and `AdamW::moments` read the state, and `ParamId::position` gives a parameter's place in its store.
- Data: `Targets`, `Dataset`, `Batch`, `BatchView` and `Batcher` (shuffled batches whose smaller last batch reuses the full-size buffer).
- Training: `Trainer` (one step at a time; `step` returns the batch's loss or the health checks' error at the step that meets it), `Loss` (cross-entropy, NLL, MSE, L1, Huber, smooth L1, BCE, BCE with logits, KL divergence), `fit` and `fit_with_hooks` with `FitConfig`, `OptimizerConfig`, `LrSchedule` (constant, or cosine as PyTorch's `CosineAnnealingLR` stepped once per epoch), `History` and `EpochReport`, and `accuracy`. `fit` checks the data against the loss and the model before it trains and returns `Error::InvalidData` instead of panicking, naming the tensors and their shapes ("the inputs are [8, 5]", "the value targets are [1437, 1], but the model outputs [1437, 10]", "there are 100 rows but 99 labels"), including binary cross-entropy targets that are NaN or outside `[0, 1]`, and inputs of the wrong width (the message gives the width that reaches the layer when an activation or `Glu` comes before the first layer that names one); it also rejects any NaN or infinite input or value target, naming the row, the column and the value (two layers that disagree still panic in the forward pass, naming both); `accuracy` panics on a label not below the output width, as `fit` rejects it. The same seeds give bit-identical parameters for any thread count on the same machine and kernel level.
- Hooks: `Hooks` (with `HookId`) runs closures on chosen layers after each forward or backward pass; each sees a `LayerEvent` with the layer's input, output, local derivative and the gradients with respect to its output and input.
- Neuron masks: `NeuronMask` with `Sequential::set_mask`, `clear_mask` and `mask`; an off neuron outputs exactly 0 and passes no gradient.
- Health checks: `Health` (with `OnNonFinite`), `HealthMonitor` and `Warning`. Every step checks that the loss and each gradient are finite (by default training stops with `Error::NonFinite`, naming the step and `loss` or the parameter), warns when a gradient norm is above 1e3 or below 1e-7 (no vanishing warning once the loss has fallen 10,000-fold from its first value, which is convergence) and when binary cross-entropy clamps a logarithm, and each epoch reports ReLU and ReLU6 neurons that output 0 for every sample. When the loss is the non-finite value, the error and the warning name the cause: the first NaN or infinite input or target value (its batch position, its feature and, in a hand-written loop that passes `StepInputs::rows`, its dataset row; `BadInput`; `fit` rejects such data before training, with an error that names the row), or, when every input was finite, that the values overflowed and a lower learning rate is the thing to try; nothing is scanned on a healthy step. `Trainer` also warns, at most once per epoch (`Warning::NegativeLoss`), when a loss that cannot be negative on valid inputs (`Loss::non_negative`) comes out below 0, for example `Loss::Nll` on scores that are not log-probabilities. `HealthMonitor::after_backward` takes the step's `StepInputs`; `HealthMonitor::with_loss` turns the negative-loss check on for a hand-written loop. Every warning ends with a hint on what to try, and `Warning` has accessors (`kind`, `step`, `epoch`, `location`, `layer`) with `WarningKind`. Warnings go to a sink closure, which receives every one of every epoch, or to standard error, where printing is bounded: a layer's dead-neuron report (`247 of 256 (96%)`, the first 10 indices) is printed when its share first passes 25%, 50% or 90%, so a healthy run prints nothing, and an exploding or vanishing parameter is printed once and then summarised in one line per kind each epoch. `Health::quiet()` keeps every check and drops the warnings. A neuron masked on the `Linear` before a ReLU layer is not reported dead.
- Inference: `InferenceModel::compile` turns a `Sequential` and its parameters into a model that runs without the training graph; `infer` runs one input through the matvec kernels on the calling thread and `infer_batch` a batch through the GEMM. `InferenceLayer` and `Layer::inference` give every built-in layer an inference form.
- `save`, `load`, `load_lenient` and `load_with`: weights in the safetensors format, named as a PyTorch `state_dict`. Files written by `save` load in PyTorch with `safetensors.torch.load_file` (checked by `make_fixtures.py --check-rust-save` against a committed file that `save` must reproduce byte for byte), and files saved by PyTorch load here. `load_lenient` and `load_with` return the keys of the file they ignored (`load_with`: none when `strict`). `load_with` takes `LoadOptions` (`strip_prefix("module.")`, or a `rename` closure for shifted indices; `strict` applies to the renamed keys; two keys renamed to one are an error naming both). Loading checks every key, shape and the F32 type before it writes anything, and a `torch.save` file (a zip archive or a pickle) gets an error that says to save with `safetensors.torch.save_file`.
- After a warm-up, a training step, a hooked or masked step, the health checks and both inference paths allocate nothing.
- `Level` and `Warning` are `#[non_exhaustive]`, so a later kernel level or warning is not a breaking change; a `match` on either needs a wildcard arm.
- `Default` for the parameterised activations with PyTorch's defaults (`Gelu` exact, `LeakyRelu` slope 0.01, `Elu` and `Celu` alpha 1, `Softplus` beta 1 and threshold 20, `Hardtanh` -1 to 1), and `Trace::with_capacity` is public so a manual loop can size its trace once (it saves the first pass's allocation). The docs now say that `AdamW`'s default decay can keep a run from settling on a minimum away from 0, that "dead" neurons are measured per epoch and per data, why a PyTorch loop's mean loss differs from `EpochReport::mean_loss` when the last batch is short (with the loop that matches), and how to rebuild the digits split outside the repository.
- Layers and masks by `Linear`: `Sequential::linear`, `linears` and `param` (`"2.bias"`, no allocation), `as_linear` on `dyn Layer` (sealed: only `Linear` answers it), `Layer::parameter` and `Layer::is_elementwise` (which says where a neuron mask lands), `Linear::from_values` for weights trained elsewhere, `NeuronMask::from_off`, `from_on`, `all_off`, `on`, `off` and collecting from bools, and `Sequential::neuron_layer`, `set_neuron_mask`, `neuron_mask`, `clear_neuron_mask` and `set_neuron`, which address a hidden neuron by its `Linear` and put the mask on the last layer of the run of element-wise layers after it (on `Linear → Tanh → Sigmoid` the `Sigmoid`, so an off neuron sends exactly 0), or on the `Linear` itself when no element-wise layer follows (`set_neuron` on an existing mask allocates nothing). `set_neuron_mask` and `set_neuron` check the mask's width against the `Linear`'s output width at once and panic naming the `Linear` and both widths, and refuse to add a neuron mask while the `Linear` itself carries a mask set with `set_mask` (which `neuron_mask` and `clear_neuron_mask` do not see), so one set of neurons never carries two masks. The health check's dead-neuron report treats a mask anywhere in that run as deliberate.
- Held-out measurement: `Evaluator` (`new`, `refresh`, `evaluate`, `misclassified`) and the one-shot `evaluate` return an `Evaluation` with the loss (each batch's training loss weighted by its row count, as `EpochReport::mean_loss` is), the accuracy for class targets and R² for value targets (scikit-learn's `r2_score`, averaged over the outputs); they run the compiled inference model, or the tape for a model with a layer that has no inference form, return `Error::InvalidData` for data that does not suit the model or the loss (a label not below the output width names the row, the label and the width), and allocate nothing once they have seen data of that shape (`refresh` aside), on either path. `refresh` copies new weights into the compiled model in place unless a clone shares them or the layout changed, when it compiles afresh; the mask values are each evaluator's own, never a clone's, and are copied in place whenever the masks sit on the same layers. `Evaluator::with_neuron_masks` gives chosen `Linear`s' neurons a mask, and `Evaluator::set_neuron_mask` switches them per evaluator without allocating, compiled or on the tape (where it changes the evaluator's own copy of the model), for an ablation sweep; `refresh` keeps those masks. `Evaluation` is `#[non_exhaustive]`, so a later measure is not a breaking change. `accuracy`'s docs point to `evaluate`, which returns an error where `accuracy` panics. `Dataset::split_at` and `Dataset::subset` copy rows out of a data set.
- Reading a network outside training: `InferenceModel::infer_batch_observed` calls a closure with each layer's output (masked, as the next layer receives it) as the batch runs, in layer order; a `Linear` fused with the ReLU after it reports the ReLU's layer only. The keep values of a compiled model's masks now belong to each instance, so clones share the weights but not the masks: `InferenceModel::compile_with_neuron_masks` adds an all-on mask step for chosen `Linear`s' neurons (at `Sequential::neuron_layer`), and `InferenceModel::set_neuron_mask` changes one in place without allocating; `compile_with_masks` and `set_mask` do the same by layer index (`Error::Unsupported` for neurons or a layer with no mask step, `Error::InvalidData` for a mask of the wrong width or an index that is not a `Linear`). A new public module, `cavitation_nn::shrink`, holds the tools for shrinking a trained network, outside the crate root and the prelude: `shrink::activity` measures each neuron of chosen `Linear` layers over a data set on the batched inference path (or on the tape, for a model with a layer that has no inference form), read where its output is final (after the activations, at `Sequential::neuron_layer`), and returns a `shrink::LayerActivity` per layer (`#[non_exhaustive]`) with the mean, mean absolute value, firing share (rows above 0) and maximum; with no `Linear` listed it returns an empty list without running the data.
- `shrink::compact` removes switched-off neurons for good: it rebuilds a masked network as a smaller dense one in a new parameter store (each masked hidden `Linear` keeps the rows of its on neurons, the next `Linear` the matching columns, a per-channel `Prelu` between them the matching slopes; layer indices stay, so the result saves and loads like any network). For finite weights its outputs equal the masked network's bit for bit on the `reference` and `sse4.2` kernel levels, through `InferenceModel::infer` and, while every summed length is at most 256, through the batched paths; on `avx2`, `neon` and `accelerate`, where an output's rounding depends on its position, each network is within the documented matvec and GEMM rounding bound of the exact result. It returns `Error::Unsupported`, naming the layer and what to do, for a mask on the output layer, a removed neuron that passes an element-wise layer with f(0) ≠ 0 after the last mask that switches it off (mask by `Linear` with `set_neuron_mask` instead), a mask that does not reach the next `Linear` through element-wise layers, a layer of your own with parameters, a layer other than an activation or a `Prelu` after a `Linear` that loses neurons, and a `Linear` left with no neuron; masks with every neuron on are dropped. `as_prelu` on `dyn Layer` finds a `Prelu`, sealed the same way: only the crate's own `Prelu` answers it.
- `shrink::ablate` and `shrink::ablate_with` switch each neuron of chosen hidden `Linear`s off in turn and rank them by what its absence costs (accuracy points lost for class targets, relative loss increase for value targets), on one `Evaluator` with no recompiling per neuron; neurons already off are skipped and stay off, and the model is not changed.
- `shrink::shrink` finds the smallest network that is still as good: it removes neurons of the hidden `Linear`s a step at a time with neuron masks (levels in basis points: 10% steps to 70%, then 5% steps to 95%, each layer keeping at least one neuron), neurons whose output is 0 on every training row first and then the lowest-ranked (`shrink::Ranking`: outgoing-weight norm by default, mean activity, seeded random, or your own function given a `shrink::RankContext`), retrains after each step with a fresh optimiser (`shrink::RetrainConfig`: 3 epochs of Adam at 1e-3 by default; a NaN or infinite loss or gradient returns `Error::NonFinite`), and measures each step on a validation set (`shrink::Validation`, given or carved from the end of the training rows; there is no default). It keeps the latest step that meets `shrink::Criterion` (at most 1 accuracy point lost by default for class targets, counted in whole rows; value targets must name a loss criterion), stops after 2 misses in a row or when `on_step` returns the new `Flow::Stop`, leaves the model and parameters at the kept step (or as given if none met it), and returns a `shrink::ShrinkReport` with the baseline, every `shrink::ShrinkStep` (kept neurons, the parameter count once compacted, the validation measures, and optionally a checkpoint) and a `shrink::ShrinkWarning` when one validation row is worth more than half the allowed drop, or when `compact` will not be able to rebuild the result (`NotCompactable`, naming the layer: a layer of your own with parameters, or an element-wise layer of your own after a shrunk `Linear`; the result then runs masked). Networks whose masked neurons would still reach the next `Linear` (through a `Softmax` or a `Glu`, say) are refused with `Error::Unsupported` before any training. `Ranking`, `Criterion`, `Validation` and `ShrinkWarning` are `#[non_exhaustive]`.

### Data, examples, guide and benchmark

- `cavitation-datasets`: loaders for the scikit-learn 8×8 digits (included in `data/digits/`) and for MNIST (downloaded by `scripts/data/get-mnist.sh`); a malformed MNIST header, including dimensions whose product overflows `usize`, returns `Error::Format`.
- `cavitation_datasets::cifar10`: `load` reads CIFAR-10's binary version (`data_batch_1.bin` to `data_batch_5.bin` and `test_batch.bin`, downloaded and checked against the published MD5 by `scripts/data/get-cifar10.sh`) into 50,000 training and 10,000 test rows of 3,072 pixels scaled to [0, 1], and `load_batch` reads one batch file of any whole number of records; a file that is empty or not a whole number of 3,073-byte records, a label of 10 or more, or (through `load`) a file without exactly 10,000 records returns `Error::Format` naming the file.
- The `xor`, `digits` and `mnist` examples, and known-result tests: XOR, 97.50% (351 of 360) on the held-out digits, and 98.63% on the MNIST test images (ignored by default, as it needs the data).
- The guide (`book/`, built with mdBook), with its first chapter, "Backprop by hand".
- Shrinking, end to end: the `shrink_digits` example (train on 1,149 of the training digits, `shrink` on the other 288, `compact`, save; `--ablate` switches neurons off one at a time and sweeps them with `ablate`, `--lottery` trains the found size from the kept neurons' initial weights and from new random weights, for as many epochs as the pruned network had), the ignored known-result test `shrink_known_result` (ranking by outgoing-weight norm without dead neurons first removes 75% of the 384 hidden neurons, the defaults 75% too, each within 1 test point of the unpruned network), `cavitation-bench shrink` (both runs' curves, a bit-for-bit check of the compacted networks on the 360 test digits, and `infer` timed for the full and the compacted network: 6.81 µs against 1.01 µs, 6.77× faster, measured with `cavitation-bench shrink` pinned to one core on an Intel Celeron N5105, kernel level `sse4.2`), and the guide's chapter "Shrinking a network".
- `cavitation-bench` (`all`, `mnist`, `cifar`, `digits`, `latency`, `gemm`, `subnormal`, `small`, `info`) times training and inference against a numpy baseline measured in the same run on the same network, batch, data and step count. Measured with `cargo run --release -p cavitation-bench -- all` on an Intel Celeron N5105 (4 cores, SSE4.2, no AVX), release build, kernel level `sse4.2`, 4 threads, plain SGD, numpy 2.4.4, rustc 1.99.1 (the figures of this run): an MNIST epoch of the 784 → 1024 → 256 → 10 network takes 6.17 s at batch 128 (numpy 9.35 s) and 10.19 s at batch 32 (numpy 14.61 s); the digits network trains at 116,904 samples/s (numpy 86,787); one input through the digits network in inference mode takes 6.77 µs (numpy 32.35 µs). `small` trains a small network at 1 and at 4 threads, each in its own process, and prints the wall-clock and CPU time of each (CPU time on Linux only). `cifar` trains the 3072 → 1024 → 512 → 10 network with Adam (lr 1e-3) on CIFAR-10's 50,000 training images at batch 128 and 32, in seconds per epoch, or with `--steps N` in steps per second over timed runs of N steps (cavitation's timed runs include the health scan at the end of each, which numpy's do not, so at small N the steps-per-second figure slightly understates cavitation); `all` leaves it out because its epochs take minutes on a small machine. Measured in a separate run, with `cavitation-bench cifar --steps 200`, on an Intel Celeron N5105 (4 cores, kernel level `sse4.2`, 4 threads, numpy 2.5.4, rustc 1.99.1, other processes using 70% of one core during the run): 12.78 steps/s at batch 128 (numpy 6.09) and 24.32 steps/s at batch 32 (numpy 12.19).
- `cavitation-bench` reads the load average on macOS too (from `sysctl -n vm.loadavg`), so its report no longer says "load average at the end unknown" there.
- Each training benchmark of `cavitation-bench` prints a summary of the health warnings it raised after its timing lines, grouped by kind and layer, with the first epoch of each group (for example `health: 4 warnings: DeadNeurons (layer 3, from epoch 1) x3; DeadNeurons (layer 5, from epoch 1) x1`), and `results.json` carries it as `health`. The summary is formatted after the timed region.
